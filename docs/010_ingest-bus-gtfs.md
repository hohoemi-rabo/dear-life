# 010 バス（GTFS-JP）の取り込み（バス停・時刻）

- 主な要件：1.1（コンテストの必須データ）、7章（バス停・時刻）、7.3（GTFS のクレジット）、11.1（ライセンス表示の確認）、4章（車0台の反映）、6.3（冬・車0台のおでかけ）
- 依存：004、005

## 目的

南信州のバスの GTFS-JP からバス停の位置と時刻を取り込み、地区ごとのバス停の数、地図表示、冬・車0台の「おでかけ」の場面（実際の便と本数）に使う。コンテスト（要件 1.1）の必須条件を満たすデータなので、ほかのデータより先に進める。

## 仕様メモ

- 入手先：GTFS データリポジトリ（https://gtfs-data.jp/ 、API は `https://api.gtfs-data.jp/v2`）。飯田市のページから案内されている
- 使うのは `stops.txt`（バス停の名前・緯度経度）に加え、`routes.txt`・`trips.txt`・`stop_times.txt`・`calendar.txt`・`calendar_dates.txt`・`feed_info.txt`（便・時刻・運行日・有効期間）。2026-10-21 に「時刻は MVP では出さない」から「冬・車0台の場面で時刻まで使う」に変えた（要件 6.3）
- 場面で使うのは、地区ごとに決めた乗り場と行き先の間の直通便だけ（乗り換えの検索はしない。経路検索は gofreely の役目）。必要な便と本数は取り込み時に計算して保存し、画面では計算しない
- 24時を超える時刻、乗降の制限（`pickup_type`・`drop_off_type`）、データの有効期間を正しく扱う。有効期間外の日を運行日と見なさない
- 更新は年1回＋ダイヤ改正時

## 決めたこと（2026-10-23）

- **取り込むフィードは3つ**（まさゆきさんと決定）。どれも提供者は南信州地域交通問題協議会（南信州広域連合）、ライセンスは CC BY 4.0
  - `Minamishinshu-Iidacity-1`：【飯田市】L1市民バス循環線／C2久堅線／C3千代線／C4三穂線／C5大休線／E2平岡線（gofreely と同じフィード）
  - `Minamishinshu-Shinnan-1`：【信南交通㈱】W0駒場線／E0阿島線／E1遠山郷線。これがないと伊賀良は三穂線の平日朝夕1便ずつだけになる
  - `Minamishinshu-iidacity-3`：【飯田市】飯田☆中津川線（12/1〜3/19 は全日運休なので、冬の場面には出てこない）
  - 電気小型バス「プッチー」（`Minamishinshu-iida-2`）は今回は入れない
- **ライセンスと表記**：リポジトリの利用規約（第5条）で、データのライセンスは提供者が指定したもの（各フィードの `feed_license`）。決まった文言の指定はないので、CC BY 4.0 の求める表示（作者・データ名・ライセンスとリンク・加工したこと）で書く。文言は `data_sources.credit_text`（取り込みのたびに作り直す）。要件 7.3 に書いた
- **取り込みは手元のスクリプト**（`npm run bus:sql`）で、Worker では取り込まない。データ自体は小さい（`stop_times` は3フィードで約5,000行）が、乗り場を地区に振り分けるのに国土地理院の逆ジオコーダを乗り場の位置ごとに呼ぶ必要があり（初回 533 か所）、Worker の呼び出し回数の上限（50回）に収まらないため。結果は 004 と同じく、マイグレーション（`*_bus_gtfs_data.sql`）にして MCP で当てる
- **Worker は新しい版の確認だけ**：処理 `bus_feeds` が毎日、取り込んだ版（`gtfs_feeds.file_uid`）とリポジトリの今の版を比べる。新しい版が出た・有効期間が30日以内に切れる／切れた・ライセンスが変わった・配布が終わった、のどれかなら処理を失敗にして Discord に知らせる（取り直すまで毎日）。外部 API は1日3回
- **バス停の地区への振り分け**：乗り場の緯度経度 → 国土地理院の逆ジオコーダで町名（`lv01Nm`）→ 004 の対応表（`createTownResolver`）。点データは境界線データを使わない方針（7.2）のまま、住所の代わりに位置から引いた町名で振り分ける。結果は `data/bus_stop_towns.csv` にためて、新しい位置だけ問い合わせる
  - 飯田市外（市区町村コードが 20205 以外）は入れない。対象外の地区（松尾・羽場など）は町名が対応表にあるか確かめたうえで入れない
  - 対応表にない町名があればスクリプトが止まる。2026-10-23 に主税町・扇町・長姫町・東和町を中心市街地として足した（まさゆきさん確認。004 の CSV は94町名になった）
- **バス停の数え方**：同じ名前・同じ地区の乗り場（向きごとの乗り場や、フィードをまたいだ同じバス停）を1つのバス停にまとめる。位置は乗り場の平均。地区の境にあって乗り場が両側の地区に分かれるバス停（睦橋）は、それぞれの地区に1つずつ数える。2026-10-23 時点で上郷11・鼎25・伊賀良16・中心市街地30
  - 画面では「このデータ（3路線群）に含まれるバス停」と書く。ほかの路線のバス停は数に入らない
- **おでかけの便の決め方**（`src/lib/gtfs/outing.ts`）
  - 乗り場・行き先はバス停の名前で探す（向きの違う乗り場もまとめる）。乗れる（`pickup_type` が 0）停留所から、降りられる（`drop_off_type` が 0）停留所までを1本で行ける便だけ。2・3（予約・申し出）も決まった便として案内できないので使わない
  - 循環線のように同じバス停を2回通る便は、降りる所の手前で最後に乗れる所から乗る
  - 後に出て先に着く便がある遠回りの便（循環線の逆回りなど）は案内しない
  - 行きは「行きの時刻以降」に出る最初の便、帰りは「帰りの時刻以降」かつ行きの到着より後に出る最初の便と、その次の便
  - 日付：1月15日以降で、その曜日に当たる最初の日（3フィードとも有効な期間の中）。年末年始と成人の日を避けるため（1月15日〜2月10日に祝日はない）。今のデータでは平日 2027-01-15・土曜 2027-01-16・日曜 2027-01-17。冬が有効期間に入っていなければ取り込みを止める
  - 本数は3つ保存する：その日の乗り場→行き先の直通便の数、行き先→乗り場の直通便の数、乗り場から乗れる便の数（行き先を問わない）
  - 運行日は calendar の曜日と期間で決め、calendar_dates の追加・運休を優先する。feed_info の有効期間外は運行日と見なさない
- **おでかけ（`data/bus_outings.csv`）**：2026-10-23 にまさゆきさんが決定。1つの地区に複数持てる（並び順1を場面に使う）。曜日は4地区とも土曜、行きは 9:00 以降・帰りは 12:00 以降

## 取り直しの手順（ダイヤ改正・新しい版が出たとき・おでかけを変えたとき）

1. `npm run bus:sql` を動かす。今の版を取り、新しい乗り場の位置だけ逆ジオコーダに問い合わせ（`data/bus_stop_towns.csv` に足される）、地区ごとのバス停の数と、おでかけの便を表示する
   - 「対応表にない町名があります」で止まったら、どの地区かまさゆきさんに確かめ、`data/iida_district_map.csv` に足して 004 の手順（`npm run town-map:sql` → 当てる）を済ませてから、もう一度動かす
   - 「バス停『…』がフィードにない」で止まったら、ダイヤ改正でバス停の名前が変わった可能性がある。`data/bus_outings.csv` を直す（まさゆきさんに確認）
   - 表示されたおでかけに `no_outbound`・`no_return`（便がない）があれば、まさゆきさんに伝えて乗り場・時刻を見直すか決めてもらう
2. 中身が変わっていれば `supabase/migrations/<版番号>_bus_gtfs_data.sql` が書き出される。`npm test` を通す
3. Supabase MCP の `apply_migration` で当て、`list_migrations` の版番号にファイル名を合わせる
4. 次の日の `bus_feeds` が `succeeded` になれば、通知は止まる
5. 取り込むフィードを足す・外すときは `src/lib/gtfs/import.ts` の `BUS_FEEDS` を直し、要件 7.3 とこのチケットも直す

## 017・018・019・021・022 への引き継ぎ

- 場面の `{本数}`（「このバス停からは土曜1日{本数}本」）は、`outbound_trips_per_day`（行き先への直通便の数）を使うのがよい。`origin_departures_per_day` は行き先を問わない数なので、文の意味と合わせて選ぶ（017）
- `next_return_*` が null のときは「次の便はありません」と書けるようにする。`status` が `available` 以外なら「この条件で使える便は見つかりませんでした」、行がない・出典が非公開・`valid_until` を過ぎたら「データ未取得」（017・018）
- 時刻は GTFS の書き方（24時以上がありうる）。今のおでかけには出てこないが、画面では「翌0:30」のように直す（015・017）
- `service_date` を「2027年1月16日（土）の時刻表」のように出典と一緒に出す（要件 6.3「出典（データの時点）つき」）
- バス停の数は `facilities`（`kind = 'bus_stop'`）を地区で数える。`attributes.route_names` に止まる路線、`attributes.stop_ids` に元の乗り場がある（019・021）
- クレジットは `data_sources.credit_text` をそのまま出す（022）
