## 目的

カルテで調べたことの中から、**現地で自分が確かめたいことだけ**を選んでおき、下見の当日にスマホの1つの画面で見返せるようにする。メモの主役は「現地で何を見るか・何を聞くか」。相場・件数・出典などの詳しい情報はカルテに置いたままにし、メモからはリンクでたどる。

## 指示書で決まっていること（`docs/design/shitami-memo-instructions.md`）

- 新しいページは作らない。**カルテ一覧の下の方に「わが家の下見メモ」の欄**を置く（見本では独立した画面に見えるが、指示書を優先する）
- カルテの詳細の「現地で確かめたいこと」などの近くに「**＋ 下見メモに入れる**」を置く。押すとその場で「**追加済み**」になり、画面は切りかえない。「**下見メモを見る**」でカルテ一覧のメモ欄へ移る
- メモ欄には**追加した項目だけ**を出す。項目ごとに開閉でき、「**メモから外す**」で消せる。空なら「カルテから、現地で確かめたいことを追加できます」と出す
- 最初の3項目：

| 項目 | メモに出すもの |
| --- | --- |
| バスで街へ行って帰る | 停留所の名前、当日に確かめたいこと、地図と gofreely へのリンク。時刻を出すなら、今のデータ（冬のおでかけの便）を使い、対象の日と「例」であることを書く |
| 学校のまわりを歩く | 「歩道はどこまで続いている？」「道路を渡る場所はどこ？」などの確認点と、学校・学区を見る地図へのリンク。通う学校は住む住所が決まってから確かめる、と添える |
| 古めの家で聞くこと | 「冬の暖房は？」「窓や床の断熱工事は？」「屋根や水まわりの修繕はいつ？」などの質問と、住まいのカルテへのリンク |

- 見本の「765万円」やバスの時刻を、決まった値として作らない。出すかどうかは、選んだ条件（地区・家族・車・住まい）とデータのあるなしで決める
- 端末に、**利用者が追加した項目の ID だけ**を保存する。**地区ごとに分け**、地区を切りかえても別の地区のメモが混ざらないようにする
- 今のカルテの表示・地区の切りかえ・印刷はそのまま使えるようにする。新しい地図・経路検索・gofreely 側の改修はしない
- スマホを優先する
- 作ったら「追加 → 一覧で確認 → 読み直しても残る → 地区を変えると混ざらない → 消す」とスマホの幅で確かめる

## 決めたこと（2026-11-10 まさゆきさん）

- **保存**：追加した項目の ID だけを、地区ごとに端末（localStorage）に残す。要件 2.3・8.2 と「データについて」の文言をこれに合わせて直す（サーバーには送らない・個人を特定する情報は入れない、は変えない）
- **「＋ 下見メモに入れる」を置く所**：カルテの詳細に加えて、**くらしのピンの吹き出しにも**置く（見本1枚目）。バス（冬・車0台の「バス・電車」「バス」のピン）、学校（学校のピン）、古めの家（住まいのピン）
- **バスで街へ行って帰る**：車0台のときだけ追加できる（今の「冬のおでかけ」のタブと同じ条件）
- **今の「現地で確かめたいこと」のチェックの箱**：画面ではやめて、確認点は箇条書きで残し、その近くに「＋ 下見メモに入れる」を置く。印刷の空欄の箱は残す

## 今の仕様とぶつかるところ（決める必要がある）

1. **保存**：要件 2.3 は「入力内容の保存」を MVP に入れないとしている。8.2 は端末に残すものを「公開データと、最後に見た画面の条件だけ」としている。「データについて」には「条件は URL にだけ入り、サーバーに送らず保存もしない」と書いている。下見メモの ID を端末（localStorage）に残すなら、この3か所を直す。サーバーには送らない・個人を特定する情報は入れない、は変わらない
2. **「＋ 下見メモに入れる」を置く場所**：指示書はカルテの詳細。見本の1枚目は、くらしの冬のピン（バス・電車）の吹き出しにも「＋ 下見に入れる」がある
3. **見出しの言い方**：指示書は「下見メモ」「メモから外す」、見本は「下見プラン」「プランから外す」「下見ミッション」。指示書の言い方に合わせる案
4. **今の「現地で確かめたいこと」のチェックの箱**：詳細ページには、押せるが保存しないチェックの箱がある。下見メモと並ぶと、どちらに印を付ければよいか迷う

## 上と下の使い分け（2026-11-10 まさゆきさんの指示。この節の名前が今の正）

「まずはここから」と「わが家の下見メモ」の両方に学校やバスが並び、違いが分かりにくかったため、上を「気になることを調べる入口」、下を「現地でやることを見返すリスト」に分けた。保存のキー（`dearlife:shitami-memo:<地区>`）・ID・出す条件・リンク先・欄の id（`#shitami-memo`）は変えていないので、前に入れた項目もそのまま出る。

- 上：**わが家の確認ポイント**。一言は「選んだ暮らしの条件に合わせて、気になることを調べよう。」。主ボタンは今の「◯◯を見る」。添えるボタンは「＋ 下見プランに入れる」、入れたら「✓ プランに追加済み」（その場にとどまる）。問いごとの「下見プランを見る」はやめ、見出しの近くの「下見プランを見る（N件）↓」1つにした（N は表示中の地区の数、0件は件数なし）
- 下：**わが家の下見プラン**。一言は「飯田に行った日に、見たい・試したいこと。」。閉じたままでも名前と当日にすることの一文（`summary`）を出し、詳しい中身・リンク・「プランから外す」は開いて見る。0件は「現地で確かめたいことを、上の確認ポイントから追加できます。」
- 当日の一文：バス「停留所まで歩き、行きと帰りの便を確かめる。」、学校（名前を「学校のまわりを親子で歩く」に）「歩道が続いているか、どこで道路を渡るかを見る。」、古めの家「見学のときに、冬の暖房や断熱、修繕のことを聞く。」（古めの家の一文は Claude の案）
- カルテの詳細・くらしのピン・印刷の言い方も「下見プラン」にそろえた
- 確かめたこと：PC・スマホで、前のデータが出る → 追加で件数が増える（画面は動かない）→「下見プランを見る」で下へ → 閉じたまま当日の一文が読める → 外すと件数が減る → 0件の案内。画像は `~/dear-life-screenshots/2026-11-10-shitami-plan/`
