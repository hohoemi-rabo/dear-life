# 007 相場の集計 SQL 関数と 5.1 の値の検証

- 主な要件：5章-4〜7（土地・中古戸建て・件数ラベル・言いかえ）、5.1（現在の集計結果）、9.3（集計は SQL 関数で）
- 依存：006

## 目的

取引データから地区ごとの相場を Supabase の SQL 関数で集計して `market_stats` に保存し、要件 5.1 の表と一致することを確かめる。

## 仕様メモ

- **土地**：種類「宅地(土地)」。㎡単価の真ん中の値（中央値）＋下位25%〜上位25%の幅。㎡単価が空の行は総額÷面積で補う。坪単価（㎡単価×3.3058）と「200㎡（約60坪）なら約○万円」も出せるようにする
- **中古戸建て**：種類「宅地(土地と建物)」で用途に「住宅」を含むもの（空欄も含める）。築年数＝取引年−建築年で「築20年以内」「築21年以上」に分け、総額の真ん中の値。建築年不明はどちらにも入れない
- **件数ラベル**：30件以上「件数じゅうぶん」、10件以下「件数少なめ・参考程度」、11〜29件「参考になる件数」（2026-10-24 にまさゆきさんと決定）
- 新しめ（築20年以内）は4地区とも12件以下なので、えらぶ画面の返事に必ず「件数少なめ・参考程度」を付ける（4章）。ラベルの判定を画面側と共通にする
- 集計は取り込みのあとに Worker から RPC で呼ぶ

## 006 からの引き継ぎ（2026-10-23）

- 取引は `real_estate_transactions` に入っている（2021〜2026年、1,313件）。種類は `property_type`、㎡単価は `unit_price_per_sqm`（空は null）、面積は `area_sqm`、建築年は `building_year`（「戦前」・空は null）、用途は `use`（空は null）、除外は `is_excluded`、地区は `district_id`（対象外・対応表にない町名は null）
- **成約価格（6件）も含めて集計する**。`price_category` で区別できるが、5.1 の値は両方を含めたときに一致する
- 保存した行から `percentile_cont` で計算し直すと、2021年第1四半期〜2026年第1四半期で 5.1 の4地区の全項目が一致した（006 の確認で使った SQL の形：除外と地区なしを外し、土地は `coalesce(unit_price_per_sqm, trade_price / area_sqm)`、戸建ては `use is null or use like '%住宅%'`、築年数は `trade_year - building_year`）
- **対象期間の四半期の数を決める必要がある**。要件 5章-1 は「直近20四半期」だが、5.1 の期間（2021年第1四半期〜2026年第1四半期）は両端を含めて21四半期ある。20四半期（2021年第2四半期から）にすると 5.1 の値とずれる。着手するときにまさゆきさんに確認する
- `data_sources.period_label` は今、取り込みの範囲（最新から20四半期前まで＝21四半期）を書いている。集計の期間を決めたら、それに合わせる
- 集計は、取り込みで行が書かれた日（`transactions` の `rowsWritten > 0`）に呼べばよい

## 作ったもの（2026-10-24）

- **`refresh_market_stats(p_period_from text, p_period_to text)`**（`supabase/migrations/20261024063022_market_stats_refresh.sql`）：期間（例：`2021Q1`〜`2026Q1`、両端を含む）の取引から、4地区×3種類の12行を `market_stats` に入れ直し、書いた行数を返す。service_role だけが呼べる
  - 除外・地区なし・期間外の取引は外す。土地は `coalesce(㎡単価, 総額÷面積)`、戸建ては用途が空か「住宅」を含むもの。築年数 ≤ 20 が築20年以内、建築年不明はどちらにも入れない
  - 中央値・25%・75% は `percentile_cont`（pandas と同じ線形補間）。値は丸めずに保存し、丸めは画面で行う。25%・75% は土地だけ
  - 取引のない地区×種類も件数0・値 null の行にする（「該当なし」。行がなければ「データ未取得」）
- **Worker**：`transactions` の Job が、取り込みのあと毎日 `refresh_market_stats` を呼ぶ。期間は取り込みと同じ `QUARTERS_KEPT_BEFORE_LATEST`（最新の四半期から20四半期前まで）。取り込みがない日も呼ぶのは、計算が Supabase の中だけで軽く、集計だけ失敗した日があっても次の日に追いつくため
- **本番の確認**：2026-10-24 に `refresh_market_stats('2021Q1', '2026Q1')` を手で流し、`supabase/verify/market_stats_5_1.sql` が0行（12項目すべて 5.1 と一致）になることを確かめた。丸めなくても 5.1 の値そのものになった
- `data_sources.period_label` は取り込みの期間（2021年第1四半期〜2026年第1四半期）のままで、集計の期間と同じ
- 画面の側：`market_stats.sample_count` を `countLabel()`（`CountBadge`）に渡す。土地の坪単価（×3.3058）と「200㎡なら約○万円」は保存せず、画面で ㎡単価から計算する（015・016・019）

## 参照ファイル

- `data/aggregate_iida.py`：集計方法の基準（pandas）。入力は取引 CSV（cp932）だが、本番では API から取った `real_estate_transactions` を使う
- `data/iida_district_summary.csv`：集計結果の正解データ。対象4地区以外の地区と「戸建て（築年数を問わない）」の列も入っている。検証では4地区の行を使う
- 築年数の境目：築年数 ≤ 20 が「築20年以内」、それより大きいと「築21年以上」（取引年・建築年は年だけで計算）
