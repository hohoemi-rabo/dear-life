# 009 市オープンデータの取り込み（避難場所・公共施設・補完データ）

- 主な要件：7章（避難場所・公共施設・学校/保育の補完）、7.3（PDL1.0 の出典表記）
- 依存：004、005

## 目的

飯田市オープンデータ（PDL1.0）から、指定緊急避難場所・公共施設・教育機関・子育て施設を取り込む。

## 仕様メモ

| データ | 入手先 | 更新 |
| --- | --- | --- |
| 避難場所 | 市「指定緊急避難場所一覧」（2025-12-19更新） | 年1回 |
| 公共施設 | 市「公共施設一覧」（2025-06-23更新） | 年1回 |
| 学校の補完 | 市「教育機関一覧」 | 年1回 |
| 保育施設の補完 | 市「子育て施設」（2024-11-05更新） | 年1回 |

- 出典表記は「出典：飯田市オープンデータ『指定緊急避難場所一覧』を加工して作成」のようにデータ名ごとに書く。書き方は市の「PDL1.0に関する重要情報」に合わせる
- 公共施設は「暮らしに関係するもの」に絞る。載せる種類はデータを見てから決める（2.2）
- CSV の取得 URL が固定なら Worker で自動、そうでなければ手動取り込みのスクリプトにする
- 緯度経度がない行は住所から求めるか、地図に出さずに一覧だけにするかを決める

## 教育機関一覧・子育て施設の取り込み（2026-10-24）

| ファイル | 役割 |
| --- | --- |
| `src/lib/city/open-data.ts` | オープンデータのページから CSV の URL と更新日を探す・クレジット（PDL1.0）を書く |
| `src/lib/city/childcare.ts`・`education.ts` | CSV を施設の行にする・SQL を作る |
| `scripts/build-childcare-sql.mjs`・`build-education-sql.mjs` | `npm run childcare:sql`・`education:sql`。市のページと CSV を取り、`supabase/migrations/<版番号>_childcare_data.sql`・`_education_data.sql` を書き出す。前と同じ中身なら何もしない（共通の処理は `scripts/lib/city-open-data.mjs`） |
| `supabase/migrations/20261024073035_childcare.sql` | 施設の種類 `after_school_club`（放課後児童クラブ）と、`data_sources` の `iida_childcare` |
| `supabase/migrations/20261024082400_citywide_schools.sql` | `data_sources` の `iida_education`、学区の地区を `iida_education` から決めるようにした（008） |
| `supabase/verify/city_facilities_coverage.sql` | XKT006 の学校で市の一覧にない学校コードと、XKT007 の施設で市のデータの 150m 以内に施設がないものを出す（0行なら抜けなし） |

手順（年1回と、市のページの更新日が変わったとき）：

1. `npm run education:sql` と `npm run childcare:sql`。対応表にない町名があれば止まるので、004 の手順で足してからもう一度。教育機関一覧を取り込み直したら、学区の地区も付け直す（`reinfolib_xkt004`・`xkt005` の `fetched_at` を空にすると、次の Cron で学区を取り直す）
2. 地区・種別ごとの数を見て、`npm test` を通す
3. Supabase MCP の `apply_migration` で当て、`list_migrations` の版番号にファイル名を合わせる
4. `supabase/verify/city_facilities_coverage.sql` を流し、0行か確かめる

決めたこと：

- 学校と子育て施設は**市のデータを画面に出す**。学校は XKT006 と学校コードがすべて一致した。子育て施設はXKT007（008）は令和5年度のままで種類と名前が古く、市の一覧にある施設をすべて含んでいたため。XKT007 は取り込み続けるが公開しない（`reinfolib_xkt007` の `is_published` は `false` のまま）
- **放課後児童クラブは施設の種類を `after_school_club` に分けた**。小学生の放課後の預け先で、保育施設と数を混ぜると「保育施設が◯か所」の数が変わってしまうため
- 同じ名前・同じ場所の行は1か所にまとめ、行ごとの年齢・定員・時間は `attributes.programs` に並べる（自然保育のっぱらは2歳と3〜5歳で2行ある）。末尾の中身のない行は飛ばす
- 住所は「所在地_連結表記」をそのまま使う（建物名まで入っている）。電話番号は入れない（画面に出す予定がないため）
- 市全体を入れる（4地区の外は `district_id` が null）。2026-10-24 にまさゆきさんと決定。画面は4地区だけを出す
- 教育機関一覧の幼保連携型認定こども園（学校種 A2）は、子育て施設に入っているので学校には入れない。学校種は文部科学省の学校コードの記号（B1 小学校・C1 中学校・D1 高等学校・F2 短期大学・H1 専修学校など）。知らない記号が来たら止める
- 教育機関一覧には更新日の記載がない（`period_label` は「更新日の記載なし」）

## 避難場所・公共施設の取り込み（2026-10-26）

| ファイル | 役割 |
| --- | --- |
| `src/lib/city/evacuation.ts` | 「指定緊急避難場所一覧」を避難場所の行にする（災害の種類・指定避難所を兼ねるか・想定収容人数） |
| `src/lib/city/public-facilities.ts` | 「公共施設一覧」から載せる種類を選び、種類を分ける（POI コードと名前で決める） |
| `src/lib/city/open-data.ts` の `buildCityFacilitiesSql` | 4つの取り込みで共通の SQL（出典をそろえ、出典ごとに施設を消して入れ直す） |
| `scripts/build-evacuation-sql.mjs`・`build-public-facilities-sql.mjs` | `npm run evacuation:sql`・`public-facilities:sql`。`supabase/migrations/<版番号>_evacuation_data.sql`・`_public_facilities_data.sql` を書き出す |
| `data/evacuation_points.csv` | 市の CSV に緯度経度がない避難場所に補う位置（まさゆきさんが確かめたもの） |
| `data/city_facility_towns.csv` | 町字が空の行を、緯度経度から国土地理院の逆ジオコーダで町名にした結果（並木通り・三穂マレットゴルフ場） |
| `supabase/migrations/20261026090604_evacuation.sql`・`20261026090606_public_facilities.sql` | `data_sources` の `iida_evacuation`・`iida_public_facilities` |

手順（年1回と、市のページの更新日が変わったとき）：

1. `npm run evacuation:sql` と `npm run public-facilities:sql`。対応表にない町名があれば止まるので、004 の手順で足してからもう一度。公共施設は、載せるか決まっていない POI コードや名前（1399「その他の公共施設」）が来たら止まるので、まさゆきさんと決めて `public-facilities.ts` に足す
2. 地区・種別ごとの数を見て、`npm test` を通す
3. Supabase MCP の `apply_migration` で当て、`list_migrations` の版番号にファイル名を合わせる

決めたこと：

- **避難場所**：市全体を入れる（4地区の外は地区なし）。災害の種類は `attributes.hazards`（`flood` 洪水・`landslide` 崖崩れ等・`earthquake` 地震・`large_fire` 大規模な火事など）、指定避難所を兼ねるかは `also_shelter`、想定収容人数は `capacity`（人）と数え方 `capacity_note`（「4平方メートルあたり1人」）。夏の場面（大雨と避難）は `flood`・`landslide` を使う想定
  - 同じ名前・同じ場所が別の ID で2回載っている行（並木通り）は1か所にまとめ、ID は `attributes.ids` に並べる。末尾の中身のない22行は飛ばす
  - 市の CSV に緯度経度がない3か所のうち、風越公園（権助）・八幡公園（中心市街地）は、まさゆきさんが確かめた位置（2026-10-26）を `data/evacuation_points.csv` から補い、`attributes.point_supplemented` を付ける。出典の「加工して作成」にも位置を補ったことを書いた。市の CSV に位置が載ったらスクリプトが止まるので、そのときはこの CSV から消す
  - 風越公園（妙琴）（鼎）は実在しないようなので（まさゆきさん）、位置を null のまま入れる。地図には出さず、一覧と数にだけ使う。住所から位置を作ることはしない
  - 町字が空の行（並木通り）は緯度経度から町名を引く（知久町＝中心市街地）
  - 城下グラウンドの町名「水の手町」を対応表に足した（2026-10-26 まさゆきさんの判断で中心市街地。`20261026090602_town_district_map.sql`）
  - 市の CSV のままにしたもの（2026-10-26 まさゆきさん確認）：並木通りの想定収容人数は0人、住所と町字が食い違う行（風越山麓研修センター・特別養護老人ホーム陽だまりの丘。町字に従った）
  - 追手町小学校グラウンドの町字「追手町ニ丁目」は、「二」がカタカナの「ニ」（U+30CB）で書かれていた。見た目は同じなので、町名を取り出す処理（`townNameForRecord`）で丁目の前のカタカナ「ニ」も漢数字として扱うようにした
- **公共施設**：載せる種類は 2026-10-26 にまさゆきさんと決めた（手続き・学びの場、医療・福祉、公園・運動施設、文化施設）。画面の種類は、市役所・支所／公民館／図書館／学習・交流施設／病院・診療所／福祉施設／公園／運動施設／文化施設／温泉・観光
  - 入れないもの：市営住宅（138行）、給食の共同調理場・給食センター、斎苑、最終処分場、市の課や係の窓口（「産業経済部農業課」「農業委員会事務局」など）。合わせて154行
  - POI コード 11xx は運動施設。ただし大平宿泊訓練施設（1125）は学習・交流施設にした
  - 利用できる曜日・時間・特記事項・説明・URL・通称を `attributes` に入れる。連結表記が空の施設（マレットゴルフ場の10か所）は住所を null にする
  - 町字が空の行（三穂マレットゴルフ場）は緯度経度から町名を引く（川路＝4地区の外）
