# 030 新しい版のお知らせと「更新する」ボタン

- 主な要件：8.2（PWA）
- 依存：024

## 目的

公開しても、スマホ（特にホーム画面から開いたアプリ）では古い画面が残り続け、キャッシュを消す手間がかかる（2026-11-06 まさゆきさんの相談）。

- データ（Supabase）はつながっていれば毎回最新を読むので、もともと新しくなる（024 の `offline-data.ts`）
- 画面（コード・絵）は Service Worker が端末に残した版を使い、新しい版は画面がすべて閉じられるまで待つ。スマホのアプリは閉じられないことが多い

そこで、新しい版が届いたら「更新する」ボタンを出し、押したら入れ替えて読み直す。

## 決めたこと（2026-11-06）

- **見た目はドット風**（まさゆきさん決定）。四隅を1マス欠いた太い枠と下にずらした影の窓（`globals.css` の `.pixel-window`）に、ドット絵の更新のアイコン。文字とボタンはふつうのフォント・基本色
- **地図（028）の前にやる**（まさゆきさん決定）
- 2026-11-06 まさゆきさんの確認で直した：説明の文（「更新すると、…」）は消し、見出しだけにする。「更新する」は緑だと目立たないのでオレンジ（`autumn`、`Button` の `accent`）、「あとで」は控えめな灰色の枠（`quiet`）にする
- 画面の上に出す。下には、くらし・えらぶの固定の帯とスマホのメニューがあって重なるため（2026-11-18 に、画面全体を覆って真ん中に出す形に変えた。下の「2026-11-18 更新しないと使えないようにした」）
- 勝手には入れ替えない（024 の決めごとのまま）。押したときだけ入れ替え、すぐ読み直すので、古い部品と新しい部品が混ざらない
- （2026-11-18 にやめた）「あとで」を押した版は出さない。もっと新しい版が届いたら、また出す。押さなければ今までどおり、次に開いたときに入れ替わる
- はじめて入れたとき（古い版がない）は出さない。はじめての版が受け持ったときも読み直さない
- 別のタブで「更新する」が押されたら、ほかのタブも読み直す（古い版の部品は消されるので、そのままだと画面の移動で部品が取れなくなる）
- アプリに戻ってきたとき（`visibilitychange` で見えるようになったとき）に `registration.update()` で確かめる。圏外で確かめられなくても何も出さない

## 2026-11-18 更新しないと使えないようにした（まさゆきさん）

- 「あとで」をなくした。新しい版が届いたら、画面全体を暗くして（`bg-ink/50`）真ん中にドット風の窓を出し、ボタンは「更新する」だけ
- 後ろの画面は押せず、読み上げず、キーボードでも移れない（お知らせ以外の body の子に `inert`）。Esc でも閉じない。窓は `alertdialog`・`aria-modal`、開いたら「更新する」に移る
- 読み直すと画面で書いているものが消える。このサイトで困るのはお問い合わせの本文だけなので、お問い合わせのページでは送り終えるまでお知らせを待たせる（`ContactForm` が `serviceWorkerUpdate()?.hold()`。送れたら出す。また書き始めたら待たせる。ページを離れたら待たせるのをやめる）。下見プラン・ぽてりの色は端末に残っているので消えない
- ビルドした画面（`wrangler dev`）で、版を変えた sw.js に差しかえて確かめた：お知らせが出て「あとで」はない／後ろのボタンは押せない／Esc で閉じない／Tab でも「更新する」から動かない／「更新する」で同じ URL で1回だけ読み直し、お知らせは消える／お問い合わせは書いているあいだ出ず本文も残り、送ったら出る。写真：`~/dear-life-screenshots/2026-11-18-030-update-required/`
