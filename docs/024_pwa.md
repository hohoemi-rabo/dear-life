# 024 PWA 対応

- 主な要件：8.2（PWA 対応）、8章（個人情報）
- 依存：018、019

## 目的

スマホのホーム画面に追加してアプリのように開け、圏外でも最後に見た画面を表示できるようにする。

## 仕様メモ

| 項目 | 要件 |
| --- | --- |
| ホーム画面への追加 | 名前「DearLife 飯田移住カルテ」、短い名前「DearLife」、専用アイコンとテーマ色。アドレスバーを出さない（`display: standalone`） |
| 追加の案内 | Android は追加ボタン（`beforeinstallprompt`）。iPhone は「共有 → ホーム画面に追加」の手順を短く案内 |
| 圏外のとき | 画面の部品とドット絵は端末に保存。最後に見たくらしの場面・カルテ・地区のデータは圏外でも表示し、「オフライン表示中・データは◯月◯日時点」と出す。地図の背景は圏外では出ないことを書く |
| 更新 | つながっていれば開いたときに最新のデータを読む。画面の新しい版は次に開いたときに反映 |
| やらないこと | プッシュ通知、裏での自動同期 |
| 端末に残すもの | 公開データと、最後に見た画面の条件だけ |

- 静的書き出しなので、manifest は `app/manifest.ts`、Service Worker は自前（`public/sw.js`）か、静的書き出しに対応したライブラリを使う（依存を増やす場合はライセンス・サイズ・保守状況を確認）
- Supabase の応答はネットワーク優先・失敗時にキャッシュ。静的ファイルはキャッシュ優先＋版ごとに入れ替え

## 決めたこと

- **データの圏外対応は Service Worker ではなく画面の側で行う**（仕様メモの「Supabase の応答はネットワーク優先・失敗時にキャッシュ」はそのまま）。画面が `fetchRpcWithOfflineCopy`（`src/lib/data/offline-data.ts`）で読み、読めたら Cache API の `dearlife-data` に残し、通信に失敗したら残した応答を使う。Service Worker でやると、画面が「端末のデータを使った」ことを知れず「オフライン表示中」を出せないため。4xx（キーの誤りなど）は残した応答で隠さない
- 「データは◯月◯日時点」の日付は、応答を作った日（`generated_at`、015 で用意したもの）を日本時間で出す。画面と地図で違うときは古いほう
- 知らせは画面の上（`layout.tsx` の `OfflineBanner`）に1つだけ出す。くらしの画面はデータの区切りが3つあり、区切りごとに出すと3回出たため
- **最後に見た画面**：くらし・カルテ・地区くらべ・地図の場所と URL パラメータ（条件）だけを `localStorage` に残す（`src/lib/pwa/last-view.ts`）。ホーム画面のアイコンから開くといつも入口（`/`）から始まるので、入口に「前に見た◯◯にもどる」を出す。えらぶ・データについては残さない。読むときは場所と使う文字を確かめる
- **地図のデータ**は、つながっているときに地図を開いたことがあれば圏外でも点を出す。開いたことがなければ「データを読み込めませんでした」になる（要件はくらし・カルテ・地区のデータ）。背景の地図は圏外では出ない（021 で注意書き済み）
- **端末に先に残すファイル**：画面（HTML と、画面の移動で読む `.txt`）・`_next/static/chunks` と版のファイル・ドット絵・アイコン・manifest・MapLibre の worker。合わせて88個・3.1MB（2026-10-27）。`_next/static/media`（Noto Sans JP の分割ファイル約120個と MapLibre の使わない写しで約10MB）は先に残さず、使ったときに残す
- **版の入れ替え**：Service Worker の版は `out/` の中身のハッシュ。`skipWaiting` はせず、新しい版は開いている画面がすべて閉じられたあと（次に開いたとき）に入れ替わり、古い版の部品を消す。Next.js のビルド ID が毎回変わるので、ビルドのたびに版も変わる（利用者は次に開いたときに約3MBを読み直す）
- 開発サーバー（`npm run dev`）では Service Worker を登録しない。確かめるときは `npm run preview`
- Android の追加ボタンは、ブラウザが追加できると知らせたとき（`beforeinstallprompt`）だけ出す。ブラウザの小さな案内は止めて、フッターのボタンにまとめる。iPhone・iPad は手順の文を出す。ホーム画面から開いているときは何も出さない
- アイコンは 32ドットの家と木（背景は空と草地）。Android は丸く切り抜く（maskable）ので、家と木は真ん中の円（直径の80%）に収める（テストで確かめる）。iPhone 用の 180px は 36ドット×5倍で、空と草地を広げる。テーマ色は生成り（`#F7F3EA`、`THEME_COLOR`）

## 作ったもの

- アイコン：`src/lib/pixel/art/icon.ts`（絵）、`src/lib/pwa/icons.ts`（一覧）。`npm run pixel` が `public/icons/` に書き出す
- manifest：`src/app/manifest.ts`（`/manifest.webmanifest`）。iPhone 用のアイコンと `apple-mobile-web-app-*` は `layout.tsx` の `metadata`
- Service Worker：元は `src/lib/pwa/service-worker.js`。`npm run build` のあと（`postbuild`）`scripts/build-sw.mjs` が版と一覧（`src/lib/pwa/precache.ts`）を書き足して `out/sw.js` にする。登録は `src/components/pwa/RegisterServiceWorker.tsx`
- データ：`src/lib/data/offline-data.ts`（残す・読む・オフラインの状態）、`src/components/data/OfflineBanner.tsx`
- 最後に見た画面：`src/lib/pwa/last-view.ts`、`src/components/pwa/RememberLastView.tsx`（layout）、`ResumeLastView.tsx`（入口）
- 追加の案内：`src/lib/pwa/install-prompt.ts`、`src/components/pwa/InstallGuide.tsx`（フッター）
- テスト用の Cache API：`src/test/fake-cache-storage.ts`

## 確かめたこと（2026-10-27、`npm run build` → `wrangler dev`、Chromium 幅375px）

- 入口を開くと Service Worker が入り、88個を `dearlife-static-<版>` に残す。manifest の名前・短い名前・`standalone` が出る
- カルテ（条件付き）を開いたあと圏外にして読み直すと、カルテと「オフライン表示中・データは10月27日時点」が1つ出る。入口の「前に見たカルテにもどる」から、条件付きのカルテへ圏外のまま移れる
- くらしを圏外で開き、季節を切り替えてもドット絵とフォントが出る。開いたことのない「データについて」も圏外で開ける（出典の部分は読み込めない表示）
- つながると知らせが消える
- `sw.js` の版を変えると、開いているあいだは新しい版が待ち、画面を閉じて開き直すと入れ替わって古い版の入れ物が消える。`dearlife-data` は残る
- iPhone の userAgent で、フッターに手順の文が出る。横スクロールなし
- Android の追加ボタンはヘッドレスのブラウザでは出ない（`beforeinstallprompt` が来ない）ので、テストで確かめた。実機は公開後に確かめる
