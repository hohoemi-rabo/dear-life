# 049 デモ動画（Google AI Challenge）

- 主な要件：1.1（コンテストへの応募）
- 依存：025、026（電車の時刻の市の許可）、048

## 目的

Google Japan 25周年「Google AI Challenge」（暮らしと家族の部門。締切 2026-11-30 23:59）に応募するための、90秒以内のデモ動画を作る（2026-11-22 まさゆきさん）。

## 決まっていること（2026-11-22 まさゆきさん）

- 応募は自由なので出す。ただし、電車の時刻の市の許可（026）が下りなければ応募しない。間に合わせるため、動画は先に作る
- 二重応募（公共交通オープンデータチャレンジ2026 と両方）は問題ない
- 画面のデザイン（UI）は Gemini で作った。ただし、そのときの Gemini の履歴が見つからず、録画・キャプチャを用意できない（2026-11-23）
- **そのため、Google の AI を使う機能を1つ足し、動画の「AI を活用しているシーン」はその機能を見せる**（2026-11-23 まさゆきさん。サイトはほとんどできているので、今から Gemini で画面を作り直すことはしない）。どんな機能にするかはまだ決めていない。決まったら新しいチケット（050）を作る
- 足す機能の方向（2026-11-23 まさゆきさん）：えらぶの最初の質問（住む地区）の飯田市全体の絵で、4地区の場所を押すと、そこのドット絵風の絵が本物の写真に変わっていく動画を見られるようにする。中身は 2026-11-23 に決めて、チケット 050 にした（Google Flow で前もって作る・最後はまさゆきさんの写真・はじめは全体の絵の切り出し・窓で流す）
- その前に、飯田市全体の絵（`assets/illust/common/erabu-iida-overview.png`）をまさゆきさんが差しかえ、`npm run illust` で画面用の画像を書き直した（2026-11-23）。絵の上の4地区の札（`DistrictMapLayer`）と選んだ札のピンは、機能を足すまで外した。札の位置の値（`src/lib/illust/districts.ts`）と部品は残してある。機能を足したあとに札を付け直し、札を押して選べるテストも戻す
- 動画の決まり（応募フォームより）：「デモ動画 URL（90 秒以内推奨）」「デモ動画内に AI を活用しているシーン（画面録画やキャプチャなど）を必ず使用し、応募するアイデアや成果物・制作物を紹介してください」「ご自身の YouTube チャンネルにアップロードし、公開範囲を限定公開に設定して URL を取得」
- 応募資格の注記：「Google の AI を中心的にご活用いただいた作品が対象となりますが、他社が提供する AI ツールを組み合わせてご使用いただくことも可能です」

## 作り方（2026-11-22 まさゆきさん了承）

- 本物の画面の操作を Playwright で録画する（台本どおりに自動で動かす。リポジトリには入れない）
- 録画と、まさゆきさんの Gemini の画面録画・キャプチャを、Remotion（React で動画を組み立てる）でつなぎ、字幕・タイトル・最後の URL を付けて mp4 に書き出す。Remotion もリポジトリの外のフォルダで作る
- 声は入れず字幕で見せる。BGM は入れない（2026-11-22 まさゆきさん）
- YouTube への限定公開のアップロードは、まさゆきさんが行う

## 引き継ぎ（2026-11-23、050 が終わった時点）

- AI の場面に使う機能は 050 でできた：えらぶ 01（`/erabu`）の飯田市全体の絵の赤い目印を押すと、その場所のドット絵がふわっと出て、本物の写真に変わる動画（Google Flow の Omni で作成）が流れ、終わるとひと呼吸おいて閉じる。動画があるのは上郷（神社の石段・リニアの高架）と中心市街地（駅・神社・ロータリー）の5か所。鼎・伊賀良の目印は「準備中です」の吹き出し。地区を選ぶと、その地区の札とピンだけが立つ
- 台本の 16〜30 秒（AI の場面）は、まさゆきさんが Flow で動画を作っているところの画面録画と、サイトで目印を押して動画が流れるところの録画をつなぐ
- **注意**：Playwright についてくる Chromium は H.264 の mp4 を流せない（050 で確認。動画の窓に「読み込めませんでした」が出る）。サイトで動画が流れるところは、本物の Chrome で録るか（Playwright の `channel: "chrome"`。この PC には Chrome が入っていない）、まさゆきさんが画面録画する。WebKit はこの PC では足りない部品があって起動できなかった

## 引き継ぎ（2026-11-23、1本目の下書き）

- 作業のフォルダはリポジトリの外の `~/projects/personal/dear-life-video`（Playwright 1.49 と Remotion 4.0.546）。下書きは `~/dear-life-screenshots/2026-11-23-demo-video/dear-life-demo-draft1.mp4`（89.8秒・1920×1080）
- 録画：`node rec/ai-site.mjs`・`rec/flow.mjs`・`rec/chizu.mjs` が本番のサイトを 1440×810 で操作し、CDP の screencast でコマを `frames/<名前>/` に保存する（カーソルは画面に描いた偽物）。`frames/<名前>/marks.json` に場面の時刻が出る。コマから `public/clips/<名前>.mp4` を作るのは Remotion の ffmpeg（`npx remotion ffmpeg -f concat …`）
- サイトの動画はこの Chromium では H.264 を流せないので、録るときだけ同じ映像を VP9 に直したもの（`webm/`）を渡した。サイトで目印を押して流れるところも自動で録れた
- 組み立て：台本と秒は `src/timeline.ts`、見た目は `src/Demo.tsx`。書き出しは `npm run render`（約2分半）
- AI の場面の前半は、まさゆきさんの Flow の画面録画（約2分50秒、2026-11-23 受け取り。元は `media/google-flow.mp4`）から4か所を切り出した：フレームの2枚を選ぶ（3倍速）→ 英語のプロンプト → 生成を待つ（4倍速）→ できたロータリーの動画（2倍速）。ブラウザのタブ・ブックマーク・アカウントの写真は切り取って映さない。元の録画はコマの間隔がばらばらで、そのまま使うと黒いコマが出たので、Remotion の ffmpeg で切り出し・30fps にそろえた `public/clips/flow-*.mp4` を使う。下書き2（89.5秒）は `dear-life-demo-draft2.mp4`
- 電車の時刻は本番で「データ未取得」なので、くらしの場面の字幕は「時刻表から数えたバスの情報」にした（台本の「本物のバスと電車の時刻」から変えた）
- ナレーション（2026-11-23 まさゆきさん）：最初・Google の AI・最後の3か所だけ、まさゆきさんの声を入れる（ほかは字幕だけ。BGM はなし）。文は「飯田に住んだら、わが家はどう暮らせる？ それを、家族で確かめられるサイトを作りました。」「地区の絵と、私が撮った写真を、Google の AI でつなぎました。サイトで絵の場所を押すと、ドット絵の景色が、本物の飯田に変わっていきます。」「登録はいりません。飯田への移住を考えるご家族に、使ってもらえたらうれしいです。」。元の録音は `media/narration/`、無音で区切って音量をそろえたものを `public/audio/voice-*.wav` に置き、`timeline.ts` の `NARRATION` で場面に合わせる（AI の文は2つに分け、1文目は Flow の画面、2文目はサイトで目印を押すところ）。締めを8秒にし、カルテの後半と地図の平面を少し速くして 89.4 秒。下書き3は `dear-life-demo-draft3.mp4`
