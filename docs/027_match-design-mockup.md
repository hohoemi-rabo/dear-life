# 027 画面の見た目をモックに合わせる

- 主な要件：8章（対応端末・操作性・読みやすさ）、8.1（ドット絵）、6.4（文の種類の見せ方）
- 依存：016、018、019、024

## 目的

今の画面を、デザインイメージ（`docs/design/pc_design-concept.png`・`mobile__design-concept.png`）に寄せる。ドット絵の絵柄は今のまま、並び・横幅・絵の大きさ・アイコン・色・フォント・カードの形・詰め方を合わせる。023（印刷）・025（公開）の前に行う（2026-10-27 まさゆきさん決定）。

## 決めたこと（2026-10-28 まさゆきさん）

- **フォント**：家・土地の値段（相場の大きな数字）だけ **Mochiy Pop One**、ほかは全部 **M PLUS Rounded 1c**。Noto Sans JP はやめる（候補を画面で見比べて決定）
- **アイコン**：モックの雰囲気を重視して、全部ドット絵で描く（`npm run pixel`）
- **場面の文の枠**：会話ウィンドウ風の太い黒枠をやめ、モックどおり細い枠の白いカードにする。凡例と出典の詳細は「出典・確認日を見る」の中に畳む。出典の札（出典1など）と件数ラベルは消さない
- 文言・並びで迷ったら、モックより先に決めたこと（質問の順番は地区が最初、「大切にしたいこと」など）を優先する
- **「㎡」は「m²」と書く**：M PLUS Rounded 1c は「㎡」（U+33A1）の字形が空で、ほかのフォントにも切り替わらず何も出ない（2026-10-28 カルテの確認中に見つけた）。画面に出す面積の単位は `SQUARE_METER`（`src/lib/format.ts`）を使う。ほかに画面で使っている記号（〜 ― › → ≡ ∨ ✓ など）は字形があることを確かめた。Supabase の画面用データ（`screen_data`・`map_data`）にこの範囲の文字はない
