# 026 電車（駅・時刻）の取り込み

- 主な要件：2.2（交通）、7章（駅・時刻）、7.3（クレジット）、11.1（使い方とライセンスの確認）、4章（車0台の反映）
- 依存：003、004

## 目的

電車のオープンデータから駅の名前・位置と時刻を取り込み、交通の情報としてバス停と並べて使えるようにする。

## 仕様メモ

- 2026-10-21 にまさゆきさんが追加を決めた
- 駅：SENA オープンデータ「JR飯田線の駅」（https://sena-opendata.jp/dataset/detail/35 、CSV、提供：三遠南信地域連携ビジョン推進会議、ページの日付 2024-03-28）。ページにライセンスと項目の説明がないので、利用条件を確認する
- 時刻：上り・下りの時刻の CSV をまさゆきさんが持っている。必要になったら声をかけて用意してもらう。元の入手先と利用条件も聞く
- コンテスト（要件 1.1）の必須条件は公共交通オープンデータセンター・GTFS データリポジトリのデータなので、電車のデータは「併用するデータ」になる
- 対象地区の中や近くには JR 飯田線の駅（伊那上郷・切石・飯田など）がある。どの駅を対象地区に結びつけるか（地区内の駅だけか、近くの駅も含めるか）はデータを見てから決める
- バス（010）と同じく、電車も時刻のデータを使う。画面でどう見せるか（1日の本数、朝の時間帯の本数、始発・終電など）はデータを見てから決める。点数化・「便利／不便」の判定はしない（7.3 の考え方に合わせ、事実だけを出す）
- 駅は数が少ないので、Worker の定期取得ではなく手動取り込みでもよい。更新はダイヤ改正時
- 使い道の候補（決めるのはデータを見てから）：
  - カルテの交通カードに、地区の駅と時刻の情報を出す
  - 地図に駅を出す
  - 車0台のとき、えらぶ画面の返事に駅の情報を入れる
  - 駅が使える地区では、冬・車0台の「おでかけ」の場面を電車にする（要件 6.3。バスと同じく実際の便・本数を出す）
- ドット絵に電車の部品を足す場合は 013 に Todo を書き足す

## 010 からの引き継ぎ（2026-10-23）

- 冬・車0台の「おでかけ」は、010 でバスの分を `bus_outings` に入れた（4地区とも土曜・行き 9:00 以降・帰り 12:00 以降。場面には並び順1を使う。中身は 010 の「決めたこと」の表）。電車でおでかけを作る地区があるなら、同じ形（乗り場・行き先・行き／帰り／次の便・直通便の数・時刻表を見た日・有効期間の終わり）にそろえると、場面（017）とカルテ（019）が同じ扱いで済む。`bus_outings` を電車にも使うか（名前を変える・種類の列を足す）、別のテーブルにするかは、データを見て決める
- 時刻表から便を決める処理は `src/lib/gtfs/outing.ts`（直通便の検索・遠回りの便の除外・1日の本数・冬の基準日「1月15日以降で最初のその曜日」）。時刻の CSV を `GtfsFeed` の形（`src/lib/gtfs/feed.ts`）に直せば、そのまま使える
- 駅を地区に振り分けるなら、010 と同じく「緯度経度 → 国土地理院の逆ジオコーダの町名 → 004 の対応表」が使える（`scripts/build-bus-sql.mjs` の `reverseGeocode`、結果をためる `data/bus_stop_towns.csv`）
- 手動で取り込むなら、010 と同じく「スクリプトでマイグレーションを書き出し、MCP で当てる」形にすると、`npm test` で中身も確かめられる
- 出典は `data_sources` に1行足し、画面にクレジットを出せるまで（022）は `is_published = false` のままにする

## 確かめたこと（2026-10-23）

- **駅の CSV**：`https://sena-opendata.jp/uploads/dataset/270.csv`（Shift_JIS・CRLF）。94駅（豊橋〜辰野、飯田線の全駅）。項目は `No,駅名,ふりがな,起点からの距離,所在市町村,郵便番号,住所,経度,緯度`（経度が先）。住所は「豊橋市花田町西宿」のように番地まではなく、書き方もそろっていない（県名あり・なしが混ざる）ので、地区の振り分けには緯度経度を使う
- **利用条件**：データセットのページには書いていないが、サイトの利用規約（https://sena-opendata.jp/site_policy/ ）第1条で、サイトの基本のライセンスは CC BY 2.1 JP。第6条で、出所として「①データセットのメタデータの作成者欄の組織名、②リソースの名称、③リソースの URL」の表示を求めている。表記は「三遠南信地域連携ビジョン推進会議（SENA）『JR飯田線の駅.csv』（URL）CC BY 2.1 JP、加工して作成」の形にする
- **飯田市内の駅を逆ジオコーダで町名にし、004 の対応表に当てた結果**（市内は15駅）

  | 地区 | 駅（町名） |

  | 上郷 | 伊那上郷（上郷黒田） |
  | 鼎 | 下山村（鼎下山）、鼎（鼎下山）、切石（鼎切石） |
  | 中心市街地 | 飯田（上飯田）、桜町（桜町二丁目）、伊那八幡（八幡町） |
  | 伊賀良 | なし |
  | 対象外 | 金野・千代（千栄）、天竜峡・川路（川路）、時又、駄科、毛賀（松尾）、元善光寺（座光寺） |

- **駅は地区内のものだけを結びつける**（2026-10-23 まさゆきさん決定）。伊賀良は「地区内に駅はありません」（該当なし）と出し、近くの駅は出さない。バス停（010）の数え方とそろえる
- **時刻の CSV**（まさゆきさんが用意。`data/jr_iida_line_up.csv`・`data/jr_iida_line_down.csv` に名前を変えて置いた。UTF-8・BOM つき）
  - 元は飯田市「公共交通総合案内」（https://www.city.iida.lg.jp/soshiki/10/p0182.html ）の「JR飯田線 時刻表（令和8年3月14日改正）」の PDF（画像だけの1ページ）。PDF の注記は「上片桐〜平岡間で運行している列車を記載」だけで、平日・土休日の区別はない（毎日同じ時刻として扱う）。CSV の伊那上郷の上り20本が PDF と一致することを確かめた
  - 1行目が列の名前（`駅,U01,…` / `駅,D01,…`）、2行目が種別（普通・快速・特急 ワイドビュー伊那路○号・快速 みすず）、3行目からが駅ごとの時刻。1列が1本の列車。上りは豊橋方面（上り29本）、下りは辰野方面（下り30本）
  - 駅は上片桐〜平岡と両端の辰野・豊橋だけ（あいだの駅は入っていない）。飯田・天竜峡は「着」「発」の2行がある
  - 空欄はその区間を走らない、`↓` は通過。飯田で着だけの列車は飯田止まり（特急 伊那路は豊橋〜飯田）
  - 端の駅（上片桐・平岡）より先の行き先は表にないので、列車の行き先は保存しない
- **時刻の利用条件**：市のページに利用条件の記載がない。まさゆきさんが、実装して見せてから市に許可を取る（2026-10-23 まさゆきさんの方針。個人で作っているので、企画の段階で頼んでも断られやすい）。それまでは `data_sources.is_published = false` のままにして、画面からは読めないようにする
- 平日・土休日を確かめるために、えきから時刻表などのサイトを機械的に読み取ることはしない（サイトの規約で禁じられていることが多い）。元の PDF に区別がないことで足りるとした
- **4地区の駅の1日の本数**（CSV をそのまま数えたもの。発車する列車だけで、その駅止まりの列車は数えない）

## 決めたこと（2026-10-23）

- **保存の形**：駅は `facilities`（`kind = 'train_station'`、出典 `sena_iida_line_stations`）、時刻は新しい表 `train_departures`（出典 `iida_jr_timetable`）。駅と時刻は利用条件が違うので、出典も表も分けた。駅だけ先に公開することもできる
  - `train_departures` は「4地区の駅を発車する列車」を1本1行で持つ（地区・駅名・上り／下り・発車時刻・種別・列車の名前）。その駅止まりの列車（飯田着だけの列車など）と通過する列車は入れない。本数・始発・最終は画面の読み込み（015）で数える
- **取り込みは手元のスクリプト**（`npm run train:sql`）。SENA の駅の CSV を取り、飯田市内の駅だけ逆ジオコーダで町名にして（結果は `data/station_towns.csv`）、004 の対応表で4地区に振り分ける。時刻の CSV から4地区の駅を発車する列車を取り出し、マイグレーション（`*_train_data.sql`）にする
- 2026-10-23 に当てた中身：駅7（上郷1・鼎3・中心市街地3・伊賀良0）、発車時刻268行、おでかけ3行。Supabase の行がファイルと同じであることを確かめた
- **冬・車0台のおでかけに電車も使う**（まさゆきさん決定）：駅のある3地区は、場面にバスと電車の両方の便を出す。必須のバスを場面に残したまま、「バスも電車もある」ことを見せるため。伊賀良は駅がないのでバスだけ
  - 乗る駅と行き先（`data/train_outings.csv`）、行きは 9:00 以降・帰りは 12:00 以降（バスとそろえた）

    | 地区 | 乗る駅 → 行き先 | 行き | 帰り／次の便 | 直通（行き/帰り） | 乗る駅の本数 |
    | --- | --- | --- | --- | --- | --- |
    | 上郷 | 伊那上郷 → 飯田 | 09:29→09:34 | 13:05／14:08 | 20/18 | 38 |
    | 鼎 | 鼎 → 飯田 | 09:00→09:08 | 12:19／13:25 | 19/19 | 38 |
    | 中心市街地 | 飯田 → 天竜峡 | 09:42→10:08 | 12:33／13:25 | 19/19 | 38 |

  - **特急は使わない**（特急券が要るため）。便にも本数にも入れない（天竜峡の帰りは特急 12:25 ではなく普通の 12:33 になる）。乗る駅の本数は上り・下りの合計
  - 便の選び方はバスと同じ（`src/lib/gtfs/outing.ts` の `chooseOutingTrips`。追い越される便を除き、行きの到着より後の帰りの便とその次の便）。保存先は `bus_outings` と同じ形の `train_outings`。電車の時刻表には曜日の区別がないので、時刻表を見た日と有効期間の終わりは持たず、ダイヤの時点は `data_sources.period_label` で出す
- 逆ジオコーダの問い合わせとリトライは、010 と共通の `scripts/lib/geocode.mjs` に移した（`scripts/build-bus-sql.mjs` もこれを使う。動かして「変更なし」になることを確かめた）

## 全国鉄道運行本数データ（2026-10-24 に確かめた）

- **使い方の方針（まさゆきさん）**：時刻は今のまま市の PDF を書き写したデータを使う（許可を取るのもこのデータ）。運行本数データは、本数の確かめと、許可が出なかったときの代わりの候補として記録しておくだけで、いまは取り込まない
- 出所：「全国鉄道運行本数データ公開ページ」（https://gtfs-gis.jp/railway_honsu/ 、ベータ版）。2026年版は 2026年3月のダイヤで、JR東海は「JTB時刻表 2026年3月」から数えたもの。最終更新 2026-05-14
- ライセンス：ページには「データのライセンスはCC-BY 4.0、ODbLとします」とだけある。どちらかを選べるのか、両方に従うのかは書いていない。使うことになったら、データ説明資料（`20240424_document.pdf`、まだ読んでいない）で確かめる
- 中身：**平日の定期列車だけ**で、特急のように運賃以外の料金が要る列車と、通過する列車は数えない。駅ごと・方向ごとの着数・発数と、駅の緯度経度がある。時刻・時間帯・土休日の本数はない
- ファイル：駅ごとのデータは `unkohonsu2026_eki_sjis.csv`（事業者別・駅別。合計の列あり）と `unkohonsu2026_rosen_eki`（路線別・駅別）の2つ。4地区は飯田線だけなので、どちらも同じ数になる。前者を手元の `data/local/`（コミットしない）に置いた。区間別のデータは区切りが粗い（4地区は「天竜峡〜飯田」「飯田〜伊那大島」の2区間）ので使わない
- **市の PDF の時刻と1本単位で一致した**（特急を除いた数）。4地区の駅の1日の発の合計は 38本（元善光寺は39本）。飯田は下り発19・上り着20／発19。下りの快速みすずは飯田始発で桜町・伊那上郷に止まらないので、この2駅の下りは18本になる。上りの快速みすずは飯田止まり
- 許可が出なかったときの代わりの候補：駅の場所（SENA）＋このデータの1日の本数＋JR東海の公式時刻表へのリンク。この場合、おでかけの場面の「何時何分の便」と、カルテの始発・最終は出せなくなる

## 取り直しの手順（ダイヤ改正のとき）

1. 市のページ（https://www.city.iida.lg.jp/soshiki/10/p0182.html ）に新しい時刻表が出たら、まさゆきさんに `data/jr_iida_line_up.csv`・`data/jr_iida_line_down.csv` を作り直してもらう（形は上の「時刻の CSV」と同じ）
2. `src/lib/train/import.ts` の `TIMETABLE_REVISION`（改正日と「令和◯年◯月◯日改正」）を直す
3. `npm run train:sql` を動かす。4地区の駅と、上り・下りの本数・始発・最終、おでかけの便が表示されるので、PDF と見比べる
   - おでかけに `no_outbound`・`no_return`（便がない）があれば、まさゆきさんに伝えて乗る駅・時刻を見直すか決めてもらう
   - 「時刻は H:MM」「前の駅より早い」などで止まったら、CSV の書き写しの誤り。該当の列車と駅が表示される
   - 「駅『…』が時刻の CSV にない」で止まったら、CSV の駅名の書き方を SENA の駅名にそろえる
   - 「対応表にない町名があります」で止まったら、010 の手順と同じく 004 の対応表に足してから動かし直す
4. 中身が変わっていれば `supabase/migrations/<版番号>_train_data.sql` が書き出される。`npm test` を通す
5. Supabase MCP の `apply_migration` で当て、`list_migrations` の版番号にファイル名を合わせる
