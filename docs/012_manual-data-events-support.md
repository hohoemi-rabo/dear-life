# 012 支援制度と地区の行事（手入力データ）

- 主な要件：7.1（行事の項目）、7.2（行事の扱いのルール）、7.3（行事の表記）、10章（運用）、10.1（行事の集め方）、F-13
- 依存：003

## 目的

まさゆきさんが Supabase の Table Editor で入力する「支援制度」と「地区の行事」を、入力しやすく・間違えにくい形で用意する。MVP では専用の管理画面は作らない。

## 仕様メモ

### 地区の行事（`district_events`）

| 項目 | 内容 |
| --- | --- |
| 地区 | 4地区のどれか。中心市街地は元の地区名（丸山・東野・橋北・橋南）も持つ |
| 行事名 | 地区で使われている名前 |
| 季節・時期 | 春夏秋冬と「例年◯月ごろ」。日付は持たない |
| 範囲 | 地区全体／区（分館）ごと。区ごとなら画面で「区によって違います」と出す |
| 参加のしかた | 自由参加／区や組ごと／子ども向け など。事実だけ |
| 行事の絵 | 種類（祭り・運動会・文化祭など）→ 013 のドット絵 |
| 子ども向けか | 秋は子どもありなら子ども向けを優先して出す（4章） |
| 出典・確認日 | 資料名と年度、または問い合わせ先／最後に確かめた日 |
| 公開フラグ | 確認が済んだものだけ画面に出す |

- 個人名・個人の連絡先を載せない。「義務」「負担が重い」などの評価を書かない
- 目標：4地区×4季節×1〜2個＝16〜32件
- 表記：「地区の行事は、飯田市の公民館資料や地区公民館の情報をもとに独自にまとめたものです。年によって変わることがあります」＋資料名・確認日

### 支援制度（`support_programs`）

- 制度名・概要・対象の分野（移住／子育て など）・公式ページのリンク・確認日
- 「対象になります」と判定しない。必ず公式ページと窓口へつなぐ
- 月に1回、まさゆきさんが確認して確認日を更新

## Table Editor での入力手順

Supabase のダッシュボード（https://supabase.com/dashboard/project/ywugkkofnqkpnzkmucyv/editor ）→ 左の一覧で `district_events`（行事）か `support_programs`（支援制度）を選ぶ。

### 新しく入れる

1. 右上の「Insert」→「Insert row」を押す。右に入力欄が出る
2. 下の表のとおりに入れる。選択肢の列はプルダウンから選ぶ（打ち込まない）
3. `id`・`created_at`・`updated_at` は空のままにする（自動で入る）
4. `is_published` は **false のまま** 保存する。内容を見直してから true にする
5. 「Save」を押す。赤いエラーが出たら、下の「よくあるエラー」を見る

### 行事（`district_events`）の列

| 列 | 入れるもの | 例 |
| --- | --- | --- |
| `district_id` | `kamisato`（上郷）・`kanae`（鼎）・`igara`（伊賀良）・`chushin`（中心市街地）のどれか | `chushin` |
| `chushin_area` | 中心市街地のときだけ、丸山・東野・橋北・橋南から選ぶ。ほかの地区では空（NULL） | 東野 |
| `name` | 地区で使われている行事名 | 東野区民運動会 |
| `season` | 春・夏・秋・冬 | 秋 |
| `timing_note` | 「例年◯月ごろ」。日付は入れない | 例年10月ごろ |
| `scope` | 地区全体／区ごと。区（分館）ごとに中身が違うなら「区ごと」 | 地区全体 |
| `participation` | 自由参加／区や組ごと／未確認。わからなければ「未確認」 | 自由参加 |
| `participation_note` | 補足があれば事実だけ（空でよい） | 小学生の部あり |
| `is_for_children` | 子ども向けなら true | false |
| `art` | 祭り・運動会・文化祭・その他（場面の絵の種類） | 運動会 |
| `source_note` | 資料名と年度、または問い合わせ先（「◯◯公民館に問い合わせ」） | 飯田市公民館活動記録（令和2年度） |
| `checked_on` | 最後に確かめた日 | 2026-11-01 |
| `sort_order` | 同じ地区・季節の中の並び順。小さいほど先（ふつうは 0 のまま） | 0 |
| `is_published` | 見直しが済んだら true | false |

書かないこと：個人名・個人の電話番号やメール、「義務」「負担が重い」などの評価。

### 支援制度（`support_programs`）の列

| 列 | 入れるもの |
| --- | --- |
| `name` | 制度名（公式ページの名前に合わせる） |
| `summary` | 1〜2文の概要。「対象になります」などの判定や、「お得」などの評価は書かない |
| `category` | 移住・子育て・住まい・その他 |
| `official_url` | 公式ページの URL（`https://` から） |
| `checked_on` | 公式サイトで最後に確かめた日 |
| `sort_order` | 画面での並び順。小さいほど先 |
| `is_published` | 確かめが済んだら true |

### 直す・確認日を更新する（月に1回の支援制度、年1回の行事）

1. 直したい行のセルをダブルクリックして書きかえ、Enter で保存する（行の左端のボタンで入力欄を開いてもよい）
2. 中身が変わっていなくても、確かめたら `checked_on` をその日にする
3. 終わった制度・なくなった行事は、消さずに `is_published` を false にする（あとで戻せるように）

`updated_at` は保存のたびに自動で変わる。

### よくあるエラー

| エラーに出る名前 | 意味と直し方 |
| --- | --- |
| `district_events_chushin_area_required` | 中心市街地なのに `chushin_area` が空、またはほかの地区なのに `chushin_area` が入っている |
| `support_programs_official_url_check` | URL が `http://` か `https://` で始まっていない |
| `violates foreign key constraint` | `district_id` が4つの id のどれでもない（つづりの間違い） |
| `null value in column ... violates not-null constraint` | 必ず入れる列が空。`chushin_area`・`participation_note` 以外は空にできない |

### 画面への出方（018・019 で作る）

- `is_published` が true の行だけが画面に出る。false の行は画面から読めない
- その地区・季節に公開済みの行事が1つもなければ「この季節の行事は準備中です」と出る
- `scope` が「区ごと」なら「区によって違います」と添える。秋で子どもありなら `is_for_children` が true のものを先に出す

- 画面と同じ publishable key で REST から読んで確かめた
  - false のあいだは 0件
  - 一度だけ true にすると、中心市街地・秋で1件読めた（地区・元の地区名・時期・範囲・参加のしかた・絵の種類・出典・確認日がそろっている）。春で読むと 0件（＝「準備中」を出す条件）
  - 確かめたあと false に戻した
- 中心市街地で `chushin_area` を空にすると入れられないことは、`npm test`（`supabase-migrations.test.ts`）で毎回確かめている
