# 044 画面で使わないコードを最初に読まないようにする

- 主な要件：8章（スマホでの軽さ）、9章
- 依存：021・032（地図）、016（えらぶのバス停のシート）、023（印刷）、019・040（カルテ）

## 目的

2026-11-19 に、Vercel の React / Next.js のベストプラクティス（skills の `vercel-react-best-practices`）で画面全体を見直した。
ほとんどは守れていて、直すのは「その画面で使わないコードまで最初に読んでいる」2か所だけだった。

## 見直しの結果（2026-11-19）

守れていたこと：ページは Server Component のままで `"use client"` は末端だけ／Google マップは `next/dynamic` で地図を出すときだけ読む／
データは RPC 1回で、同じ Promise を使い回す／端末の保存領域と画面幅は `useSyncExternalStore`／effect の中で state を計算し直す形はない／
トップの大きな絵は `fetchPriority="high"`、ほかは `lazy`／バレル経由の読み込み・外部の解析スクリプトはない。
`server-*`（Server Actions など）は、静的書き出しなので対象外。

直す前の First Load JS（gzip 後）：`/` 131・`/erabu` 179・`/kurashi` 184・`/karte` 201・`/karte/<項目>` 203・`/kurabe` 179・`/chizu` 160（kB）

## 1. えらぶから、学区の面をつなげるライブラリを外す

- `src/lib/map/features.ts` が `polygon-clipping` を読んでいて、えらぶのバス停のシート（`BusStopMapSheet`）経由で `/erabu` の全員が読んでいた（gzip 約10 kB）
- シートは学区を出さないのに、4地区分の学区をつなげる計算もしていた
- 学区の関数（`mergeSchoolDistrictPieces`・`schoolDistrictFeatures`）を `src/lib/map/school-district-features.ts` に分け、シートは空の一覧を渡す
- 結果：`/erabu` 179 → 170 kB。`polygon-clipping` の入ったチャンクを読むのは `/chizu` だけになった。見た目と動きは変えていない

## 2. カルテ一覧の、印刷用の中身をあとから読む

- `KartePrint` が7項目の詳細のパネルを全部読むので、カルテの一覧でも7項目分が入っていた
- 印刷を外して測った差：`/karte` −25 kB、`/karte/<項目>` −4 kB、`/kurabe` −5 kB。効くのは一覧だけなので、カルテだけを直す（地区くらべは触らない）
- 「印刷する」ボタンとチェックの窓は最初から出す（位置を動かさない）。紙に出す中身だけを別のチャンクにし、画面が落ち着いたあとに裏で先読みする。ボタンから印刷するときは、届くのを待ってから印刷の画面を開く
- 受け入れた注意点（2026-11-19 まさゆきさん OK）：ページを開いた直後、先読みが終わる前にブラウザのメニュー（Ctrl+P）から印刷すると、選んだ中身ではなく画面そのままが印刷される

### 2 で作ったもの（2026-11-19）

- `KartePrint.tsx`：ボタンと選択肢だけ。中身（`KartePrintDocument.tsx`）は `import()` で読み、届いたら `useSyncExternalStore` で描き直す。読むのは、画面が落ち着いたとき（`requestIdleCallback`。Safari にはないので `setTimeout`）と、窓を開いたとき（失敗していたときの読み直し）
- `PrintControl` に `documentReady`・`onOpen` を足した。届くまでは窓のボタンが「準備しています」で押せない。Safari はタップから時間をおいた印刷を無視するので、押してから待つ形にはしていない（印刷を押したその場で呼ぶのは 023 のまま）。地区くらべは渡していないので、今までと同じ
- `KartePrintDocument.tsx` は `KartePrint.tsx` 以外から直接読み込まない（読み込むと、その画面の最初の読み込みに7項目分が入る）
- 結果：`/karte` 201 → 177 kB。`/karte/<項目>` は 203 kB のまま（詳細のページは、印刷と関係なく自分で7項目分のパネルを読んでいるため）
- PC のブラウザ（Chromium、手元でビルドしたもの）で確かめた：中身は開いてから約0.7秒で届き、窓の「印刷する」が押せて、8つすべてを選んだ紙（20ページ）が出る。エラーなし
