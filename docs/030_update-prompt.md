# 030 新しい版のお知らせと「更新する」ボタン

- 主な要件：8.2（PWA）
- 依存：024

## 目的

公開しても、スマホ（特にホーム画面から開いたアプリ）では古い画面が残り続け、キャッシュを消す手間がかかる（2026-11-06 まさゆきさんの相談）。

- データ（Supabase）はつながっていれば毎回最新を読むので、もともと新しくなる（024 の `offline-data.ts`）
- 画面（コード・絵）は Service Worker が端末に残した版を使い、新しい版は画面がすべて閉じられるまで待つ。スマホのアプリは閉じられないことが多い

そこで、新しい版が届いたら「更新する」ボタンを出し、押したら入れ替えて読み直す。

## 決めたこと（2026-11-06）

- **見た目はドット風**（まさゆきさん決定）。四隅を1マス欠いた太い枠と下にずらした影の窓（`globals.css` の `.pixel-window`）に、ドット絵の更新のアイコン。文字とボタンはふつうのフォント・基本色
- **地図（028）の前にやる**（まさゆきさん決定）
- 画面の上に出す。下には、くらし・えらぶの固定の帯とスマホのメニューがあって重なるため
- 勝手には入れ替えない（024 の決めごとのまま）。押したときだけ入れ替え、すぐ読み直すので、古い部品と新しい部品が混ざらない
- 「あとで」を押した版は出さない。もっと新しい版が届いたら、また出す。押さなければ今までどおり、次に開いたときに入れ替わる
- はじめて入れたとき（古い版がない）は出さない。はじめての版が受け持ったときも読み直さない
- 別のタブで「更新する」が押されたら、ほかのタブも読み直す（古い版の部品は消されるので、そのままだと画面の移動で部品が取れなくなる）
- アプリに戻ってきたとき（`visibilitychange` で見えるようになったとき）に `registration.update()` で確かめる。圏外で確かめられなくても何も出さない
