# 008 学区・学校・保育施設の取得（XKT004〜007）

- 主な要件：7章（小学校区・中学校区・学校・保育園・幼稚園等）、7.2（データの扱い）、10章（年1回の取り直し）
- 依存：004、005

## 目的

不動産情報ライブラリ API の XKT004（小学校区）・XKT005（中学校区）・XKT006（学校）・XKT007（保育園・幼稚園等）を取得して保存する。

## 仕様メモ

- 範囲データはタイル単位の取得。飯田市の4地区をおおう範囲のタイルを洗い出し、呼び出し回数が多ければ数日に分ける（1回 50 回まで）
  - 2026-10-24 に市全体に広げ、Workers Paid にした（下の「市全体に広げた」）
- 学校は市「教育機関一覧」、保育施設は市「子育て施設」（2024-11-05更新）で補う（補完は 009 と協力）
- 点データは住所の町名で4地区に振り分ける（004）
- 学区は「この地区の主な学区」として学校名を並べ、範囲は地図で見せる。「入学前に市で確認を」と添える
- 小学校区と地区は範囲が違うので、同じ範囲の情報として混ぜて表示しない
- 年1回（4月以降）取り直し、結果をまさゆきさんが目で確認する

動き（1回の実行で1段階だけ進める）：

1. `data_sources` の4行の取得日時を読み、日本時間の6月1日（今年。6月1日より前なら去年）より前に取ったもの・まだ取っていないものを探す。全部新しければ何もしない（API を呼ばない）
2. 学校（XKT006）→ 保育施設（XKT007）→ 学区（XKT004・XKT005）の順に、古いものを1つだけ取り直す。初回や毎年の取り直しは3日かけて終わる
3. 学校・保育施設：飯田市のもの（行政区域コード 20205）だけを残し、住所の町名を対応表に当てて `replace_facilities` に渡す（対応表にない町名は記録して通知、4地区の外は地区なし）。公開しない（画面には市のデータを出す）
4. 学区：応答を Worker で読まずにつなげて `replace_school_districts` に渡す。SQL の中で、タイルの切れ端を学校ごとに1つの MultiPolygon にまとめ、学校コードを市「教育機関一覧」（`iida_education`）の学校に当てて地区を付ける（4地区の外は地区なし）
5. 取り直した出典の `fetched_at` を更新する

決めたこと：

- **1日1段階**にした。はじめは呼び出し回数の上限（無料プランの50回）に収めるためだった。市全体にしてからは、学校・保育施設が156回ずつあり、1.5秒あけて呼ぶと1種類4分ほどかかるので、Cron の1回の実行を短く保つために続けている
- **「主な学区」は、学区の学校がある地区**とした（要件 7.2 の「点データは住所の町名で振り分ける」に合わせる。境界線データを使わない）。2026-10-24 に、4地区のバス停・駅（90か所）を学区の範囲に重ねて確かめたところ、各地区の点の多くはこの学区に入っていた。ただし地区の端は別の学区にかかる（中心市街地の点の一部は伊賀良小・松尾小・緑ケ丘中・旭ケ丘中の学区、鼎の点の一部は松尾小・緑ケ丘中の学区）。画面では「主な学区」とし、「入学前に市で確認を」を必ず添える
- **学区の範囲はタイルの切れ端を並べた MultiPolygon のまま**にした。切れ端をつなぎ直す（union）には PostGIS が要るが、手元のテスト（PGlite）で使えず、Worker で計算すると CPU 時間の上限（無料プランの10ms）を超えるおそれがあったため。面を塗るだけなら見た目は変わらない。地図で輪郭の線を引くときは、タイルの境目に線が出るので注意する（021）
- **学区の応答は Worker で読まない**。1タイル 200KB ほどあり、JSON.parse と JSON.stringify で CPU 時間の上限（無料プランの10ms）に近づくため。本文をつなげて Supabase に送り、SQL で読む。有料にしたあとも、読む必要がないのでこのまま
- 学区が取ったタイルの端に届いていたら（範囲の外で切れている）、入れずに失敗にする。学区のない地区があるときも失敗にする。どちらも前のデータは残る
- 保育施設は、学校データ（幼稚園・こども園）と福祉施設データ（保育所など）の両方に同じ施設が入っていることがある（例：「認定こども園慈光幼稚園」と「慈光幼稚園」）。**所在地が同じものは1つにまとめ**、学校データの名前・種類を使う。もう一方の名前は `attributes.other_names` に残す
- 福祉施設データの保育園は、所在地に市の名前がない（例：「白山通り3-351-2」）ので、行政区域コードで飯田市にしぼってから町名を当てる
- ~~4地区の外の学校・保育施設は入れない~~ → 市全体に広げたので、4地区の外も地区なしで入れる
- 高校・専修学校も `facilities`（`kind = 'school'`、`subkind` が学校の種類）に入れる。画面でどれを出すかは 019 で決める
- 休校区分（`attributes.closed_code`：0 調査なし・1 開校中・2 休校中）、管理者コード（1 国・2 都道府県・3 市区町村・4 民間・0 その他。福祉施設データの 5 は未確認）は保存だけする
- 取り直しの時期は6月1日にした（国土数値情報の学校データの前回の更新が 2024年6月だったため）。対象年度（`period_label`、今は令和5年度）は API 操作説明の一覧に書かれた年度を手で入れたもので、自動では変わらない。毎年の取り直しのあと、一覧の年度を確かめ直す
- 国土数値情報の福祉施設データには、都道府県ごとの公開・商用利用の条件がある（`R5_Terms_of_Use_WelfareInstitution.xlsx`）。長野県は条件のある県の一覧に入っていなかった（2026-10-24 確認）

## 市のデータとの突き合わせ（2026-10-24）

教育機関一覧：

- 4地区の小学校6・中学校5・高校5・専修学校1は、**学校コードがすべて XKT006 と一致**した。抜けも余分もない
- 市の一覧には幼保連携型認定こども園（学校種 A2）も7園入っているが、これは XKT007 の側に入っている（学校コードで一致）
- 位置の差はほとんど 100m 以内。飯田東中学校が 170m、飯田ビジネス専門学校が 676m 離れている（どちらが正しいかは未確認）

子育て施設：

- XKT007 から入れた22か所は、**すべて市の一覧にあった**（所在地か位置で一致）
- ただし種類と名前は市のほうが新しい。XKT007 で「保育所」の13か所のうち12か所は、市では「認定こども園（保育所型）」で、名前も「認定こども園◯◯保育園」になっている（例：伊賀良保育園 → 認定こども園伊賀良保育園）。XKT007 の福祉施設データが令和5年度のままのため
- 市の一覧にだけある、4地区の施設：
  - 地方裁量型認定こども園：野あそび保育みっけ（伊賀良）
  - 認可外保育所：ちびっこアパートつくし（上郷）、Kids Time（中心市街地）
  - その他：保育室コッコロ（中心市街地）、飯田市病児保育施設 おひさまはるる（鼎）、自然保育のっぱら（上郷。同じ行が2つある）

## 市全体に広げた（2026-10-24）

MVP の画面は4地区だけを出すが、今後のために市全体を入れておく（まさゆきさんの判断）。あわせて Cloudflare Workers を有料プラン（Workers Paid、アカウント単位で月5ドル）にした。

- 学校：市「教育機関一覧」（`iida_education`、`npm run education:sql`）を画面に出す。学校コードが XKT006 とすべて一致し、緯度経度もあるので、タイルを取らずに CSV 1つで市全体をまかなえる。幼保連携型認定こども園（学校種 A2）は「子育て施設」に入っているので入れない
- 保育施設・放課後児童クラブ：市「子育て施設」（`iida_childcare`）を4地区で絞らずに入れる
- 学区：XKT004・XKT005 を市全体（小学校19・中学校9）で入れる。地区は `iida_education` の学校から決める（`school_districts.district_id` は4地区の外で null）。4地区の「主な学区」は変わらない
- XKT006・XKT007：市全体を入れるが公開しない。市のデータの抜けの確認に使う（`supabase/verify/city_facilities_coverage.sql`）
- `SUBREQUEST_LIMIT` を 50 から 400 に上げた（005）

取り込んだ結果（2026-10-24、市全体）：
