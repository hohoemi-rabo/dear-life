# 013 ドット絵の生成パイプラインと試作

- 主な要件：8.1（ドット絵）、6.2（場面の作り）、6.5（既存ゲームに似せない）、11.1・11.2-2（絵柄の試作）
- 依存：002

## 目的

ドット絵をコードで作って PNG に書き出す仕組みを作り、まず季節の背景1枚と家族の試作で絵柄を決める。その後、全部の絵をそろえる。

## 仕様メモ

| 項目 | 要件 |
| --- | --- |
| 枚数 | 季節の背景4枚（地区共通）、地区の目印4つ、行事の絵6〜8個（種類別に使い回す）、家族の絵（大人・子どもの数で数パターン）。合計20枚前後 |
| 大きさ | 背景は 160×90 ドット。目印・家族・行事は背景に重ねる小さい部品 |
| 色 | 全部の絵で共通の16色程度のパレット |
| 作り方 | コードで作り PNG で書き出す。元データ（ドットの並び）を残して直しやすくする |
| 表示 | 整数倍に拡大し、`image-rendering: pixelated` でぼかさない |
| 代替テキスト | 絵ごとに、何が描かれているかの短い説明 |
| 地区の目印 | 地元の人ならわかる景色や建物（風越山・天竜川など）。何にするかはまさゆきさんが決める。写真をなぞらない |

- デザインイメージの絵はイメージ。実際はもっと粗い 160×90 のドット絵になる
- 場面は「季節の背景＋地区の目印＋家族＋行事の絵」を重ねて作る。重ねる位置（座標）も元データとして持つ
- 冬は車の有無で「車で出かける／バスで出かける」の部品が要る（4章）。夏は大雨、春は入園・入学（子ども0人なら公共施設）
- PNG は `public/pixel/` に置いて静的配信。`next/image` の最適化は使わない（unoptimized）
- 生成スクリプトは `scripts/pixel/` などに置き、`npm run pixel` で全部書き出せるようにする

## メモ（実装で決めたこと）

- 作りは `src/lib/pixel/`。パレット `palette.ts`、描く関数 `canvas.ts`、PNG の書き出し `png.ts`、絵の一覧（id・大きさ・代替テキスト）`assets.ts`、描き方 `art/`（`art/index.ts` が id → 描く関数）、場面の重ね方 `scenes.ts`
- `npm run pixel`（`scripts/build-pixel.mjs`）で `public/pixel/<id>.png` を書き出す。一覧にない古い PNG は消す。確認用に8倍の部品と4倍の場面を `.pixel-preview/` に書く（gitignore 済み・公開しない）
- 依存は増やしていない。PNG は Node の `zlib`（`deflateSync`・`crc32`）だけで、8ビットのパレット形式（0番が透明）で書く。1枚 0.3〜1KB
- パレットは16色（墨・白・薄い空・空・青・遠い山・深緑・緑・若草・桜・赤・橙・黄・肌・茶・灰）。肌色は土の道、灰色は道路や石にも使い回す。元データでは1文字（`k` `w` …、透明は `.`）で色を指す
- 小さい部品（人・雲・家）は文字の並び（`parseSprite`）で描く。背景は描く関数（四角・円・稜線の折れ線・網点）と部品の貼り付けで作る。花や花びらの位置は種を決めた擬似乱数で、毎回同じ絵になる
- 人物は墨の輪郭で囲み、輪郭のない背景から浮き出るようにした。家族は1人ずつの絵を `familyCanvas(大人, 子ども)` で並べて作る（大人1〜2人×子ども0〜3人。高さ21ドットで足元をそろえる）
- 背景の道（y=76〜86）は、家族や行事の部品を置く場所として空けておく
- 試作（2026-10-26）：`bg-spring`（160×90）と `family-a2-c1`（36×21）。家族は (62, 63) に置く
