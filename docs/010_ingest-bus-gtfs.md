# 010 バス（GTFS-JP）の取り込み（バス停・時刻）

- 主な要件：1.1（コンテストの必須データ）、7章（バス停・時刻）、7.3（GTFS のクレジット）、11.1（ライセンス表示の確認）、4章（車0台の反映）、6.3（冬・車0台のおでかけ）
- 依存：004、005

## 目的

南信州のバスの GTFS-JP からバス停の位置と時刻を取り込み、地区ごとのバス停の数、地図表示、冬・車0台の「おでかけ」の場面（実際の便と本数）に使う。コンテスト（要件 1.1）の必須条件を満たすデータなので、ほかのデータより先に進める。

## 仕様メモ

- 入手先：市のページから案内されている GTFS データリポジトリ
- 使うのは `stops.txt`（バス停の名前・緯度経度）に加え、`routes.txt`・`trips.txt`・`stop_times.txt`・`calendar.txt`・`calendar_dates.txt`（便・時刻・運行日）。2026-10-21 に「時刻は MVP では出さない」から「冬・車0台の場面で時刻まで使う」に変えた（要件 6.3）
- 場面で使うのは、地区ごとに決めた乗り場と行き先の間の直通便だけ（乗り換えの検索はしない。経路検索は gofreely の役目）。必要な便と本数は取り込み時に計算して保存し、画面では計算しない
- 24時を超える時刻、乗降の制限（`pickup_type`・`drop_off_type`）、データの有効期間を正しく扱う。有効期間外の日を運行日と見なさない
- フィード ID は `Minamishinshu-Iidacity-1`（gofreely と同じ）。gofreely 側の調べでは CC BY 4.0。配布ページで確かめる
- バス停は住所を持たないので、地区への振り分け方法を決める必要がある（緯度経度から町名を引く、または地区の範囲データを使う）。点データは境界線データを使わない方針（7.2）との関係を整理する
- ライセンス表示は確認中。確認できるまでは公開しない（未確認の間は画面で「データ未取得」扱い）
- 更新は年1回＋ダイヤ改正時
