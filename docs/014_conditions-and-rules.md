# 014 条件モデル・URLパラメータ・反映ルール

- 主な要件：F-01（質問と初期値）、F-02（条件の保持）、4章（選択の反映ルール）
- 依存：002

## 目的

選んだ条件を表す型、URL パラメータとの相互変換、4章の反映ルール（カードの並び順・場面の分岐・えらぶ画面の返事の種類）を、画面から独立した純粋な関数としてまとめ、テストで固める。

## 仕様メモ

### 条件

| 項目 | 値 | 飛ばしたときの初期値 |
| --- | --- | --- |
| 家族 | 大人の人数・子どもの人数 | 大人2人・子ども1人 |
| 住む地区 | 上郷／鼎／伊賀良／中心市街地 | （必須。案：未選択なら選ぶまで次へ進めない） |
| 家 | 買う・新しめ／買う・古め／借りる | 買う・新しめ |
| 車 | 0台／1台／2台以上（任意） | 未選択 |
| 大切にしたいこと | 住まい・子育て・学校／交通／防災／人口 から複数（任意）。支援制度は選択肢に入れない | なし |

- 氏名・住所・年齢は聞かない
- URL パラメータで持ち、サーバーに送らない・保存しない。将来の「URL で共有」でそのまま使える形にする
- パラメータ名は短く固定する（案：`d`=地区、`a`=大人、`k`=子ども、`h`=家、`c`=車、`p`=大切にしたいこと（カンマ区切り））
- 不正な値・範囲外の値は初期値に戻す（外部入力の検証）
- 静的書き出しなので、ページでは `useSearchParams()` を使う Client Component で読み、`<Suspense>` で囲む

### 反映ルール（4章）

- カルテの既定の並び：住まい → 子育て・学校 → 交通 → 防災 → 人口 → 支援制度（支援制度は常に最後）
- 大切にしたいことで選んだ分野を先に並べ、「○○に関する情報を先に表示しています」の一文を作る。選ばなかった分野も隠さない
- 子ども1人以上：「子育て・学校」を大切にしたいことのすぐ後ろへ。0人：下の方へ
- 車0台：交通カードを上げ、「本数や時間帯によっては、車なしの暮らしが難しいことがあります」を添える。1台以上・未選択：並びは変えない
- 場面の分岐：春＝子どもあり→入園・入学／なし→公共施設、秋＝子どもあり→子ども向け行事を優先、冬＝車0台→バス（駅が使える地区は電車）で出かける。時刻表の本物の便を出す（要件 6.3）／それ以外→車（凍結・スタッドレス）、冬＝買う・古め→古い家の寒さの想定文を入れてよい
- 点数化・ランキング・おすすめ判定はしない

## 作ったもの（2026-10-26）

`src/lib/conditions/` に、画面から独立した関数としてまとめた（テストは同じ場所の `*.test.ts`）。

- `labels.ts`：地区・家・車・カルテの分野の表示名。家と分野の名前は Supabase の enum（`housing_choice`・`karte_card`）と同じ文字で、型で食い違いを防ぐ。地区の名前と並びは 003 の seed と同じであることをテストで確かめる
- `model.ts`：条件の型 `Conditions` と初期値。家族の人数は大人1〜9人・子ども0〜9人
- `url.ts`：`parseConditions`・`writeConditions`・`conditionsHref`。パラメータは `d`（kamisato／kanae／igara／chushin）、`a`、`k`、`h`（new／old／rent）、`c`（0／1／2＝2台以上）、`p`（housing,childcare,transport,disaster,population をカンマ区切り）。不正な値はその項目だけ初期値に戻す。`p` は知らない分野・支援制度・重なりを捨て、既定の並びにそろえる（タップした順には左右されない）。書き出すとき、条件以外のパラメータ（季節など）は残す
- `useConditions.ts`：条件を読む・書くフック。書きかえは `router.replace`（`scroll: false`）で、履歴を増やさない。使う部品は `<Suspense>` で囲む
- `karte-order.ts`：`karteLayout` がカードの並び・上部の一文・車0台の注意書きを返す
- `scene.ts`：`planScene`（季節×条件 → 場面の軸。秋の子ども向け行事の優先、冬・古めの寒さの一文の可否も返す）、`selectSceneTemplate`・`selectSceneSentences`（017 のひな形・文の条件の列に当てはめる。null は「どちらでも」。合うものが複数なら条件がいちばん細かいもの、同じ細かさで2つ合えばエラー）

### 決めたこと（2026-10-26 まさゆきさん了承）

- カルテの並びは「大切にしたいこと（既定の並び）→ 子ども1人以上なら子育て・学校 → 車0台なら交通 → 残りを既定の順 → （子ども0人なら子育て・学校）→ 支援制度」
- 子ども1人以上で大切にしたいことがないときは、子育て・学校がいちばん上になる（「すぐ後ろ」をそのまま当てた）。質問を飛ばすと子ども1人になるので、何も選ばないときも 子育て・学校 → 住まい → … になる。要件 4章の既定の並び（住まい → 子育て・学校 → …）は、子どもの条件を当てる前の並びとして使っている
- 大切にしたいことで選んだ分野は、子どもや車の条件で動かさない（子ども0人でも子育て・学校を選べば上に置く）
- 上部の一文は、並びに効いた条件ごとに1文ずつ出す：「○○に関する情報を先に表示しています。」「子どもがいるので、子育て・学校の情報を前の方に表示しています。」「子どもがいないので、子育て・学校の情報は下の方に表示しています。」「車を持たない暮らしなので、交通の情報を前の方に表示しています。」。車0台の注意書きは交通を大切にしたいことで選んでいても出す
