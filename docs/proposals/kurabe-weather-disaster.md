## 1. 何を作るか（一文で）

地区くらべ（`/kurabe`）にタブ「いまの街と」を1枚足し、移住元として多い6都市と飯田を、**同じ出典・同じ定義の数字**で横に並べる。良い悪いの判定・色分け・おすすめはしない。

## 2. なぜ作るか（設計判断の根拠にすること）

- このサービスの主張は「飯田は暮らしやすい。雨や台風の被害が少ない」だが、今の画面にはその主張を数字で見せる場所がない（防災カルテは避難場所の数だけ）
- 「絵はイメージ、数字は本物」の原則どおり、主張を文章で書くのではなく、出典つきの数字を並べて見る人に判断を残す
- 地震・断層・南海トラフは扱わない（いつ起きるか分からないものは平年値や統計で言えないため）。雨・風・雪・水害被害額に限る
- ゲームの「装備変更の比較画面」の見た目。左が「いまの街」、右が「飯田」。間に矢印。数字が変わるのを見せるだけ

## 3. 守ること（今の原則をそのまま）

- 点数化・ランキング・おすすめ判定をしない。数字の増減に良い悪いの色をつけない（矢印は中立の1色）
- 文に「便利・おすすめ・多い・少ない・安全・安心」などの評価語を入れない（`src/lib/scenes/check.ts` と同じ基準）。「飯田は災害が少ない」とは書かない
- 中央値は「真ん中の値」、㎡は `m²` と書く（7章の言いかえ）
- すべての数字に出典・対象期間・確認日。クレジットの正は `data_sources.credit_text`
- 条件は URL だけ。保存しない。サーバーに送らない
- 数値データを自分で調べて埋めない。**値は私が手で入れる**。あなたは入れ物（CSV のひな形、スクリプト、テーブル、画面）を作り、値の欄は空にしておく。空の値は画面で「データ未取得」になること（F-09）
- タップ領域 44px 以上、`prefers-reduced-motion` でアニメーション停止、`lang="ja"`、aria の付け方は既存に合わせる
- CI はないので、`npm run test`・`npm run lint`・`npm run typecheck` を自分で回してから報告する

## 5. 並べる行（指標）

| key | 行の表示名 | 単位 | 出典 | 対象 | 飯田側の値 |
| --- | --- | --- | --- | --- | --- |
| `precip_annual` | 1年の降水量（平年値） | mm | 気象庁 平年値 1991〜2020年 | 気象官署 | 飯田市（官署） |
| `rain30_days` | 日降水量30mm以上の日数（平年値） | 日/年 | 同上 | 同上 | 同上 |
| `wind10_days` | 日最大風速10m/s以上の日数（平年値） | 日/年 | 同上 | 同上 | 同上 |
| `snow_depth_max` | 最深積雪（平年値） | cm | 同上 | 同上 | 同上 |
| `flood_damage_10y` | 住まいや店の水害被害額（直近10年の合計） | 万円（千円から換算） | 国土交通省 水害統計調査 表-25「水害原因別市区町村別一般資産等被害額」 | 市区町村、年次 | 飯田市 |
| `pop_density` | 人口密度 | 人/km² | 令和2年国勢調査 | 市区町村 | 飯田市 |
| `under15_ratio` | 15歳未満の割合 | % | 同上 | 同上 | 飯田市 |
| （既存） | 中古戸建て 築20年以内／築21年以上の真ん中の値 | 万円 | 不動産情報ライブラリ XIT001 | 都市 | **選んだ地区**（`market_stats` の既存値） |
| （既存） | 土地の m² 単価の真ん中の値 | 万円/m² | 同上 | 都市 | 選んだ地区 |

- 住まいの行だけ、飯田側が「市」ではなく「選んだ地区」になる。表の見出しで必ず区別する（例：「飯田市」「上郷（地区）」）
- 水害被害額は「一般資産等」なので、行の名前を「住まいや店の水害被害額」とし、注意書きに「道路や堤防の被害は含まない」と書く
- 東京23区の水害被害額は、表-25 に「特別区部」の行がなければ23区の合計。どちらにしたかを `data_sources` の備考に残す
- 台風の接近数は使わない（地方単位でしか出ていないため）

## 6. データの入れ物

### 6.1 テーブル（マイグレーション）

```
compare_cities
  id            text primary key        -- 'tokyo' など。'iida' も1行入れる
  name          text not null           -- 表示名
  census_code   text not null           -- 国勢調査の市区町村コード
  jma_station   text not null           -- 気象官署名
  sort_order    int  not null
  is_published  boolean not null default false

compare_city_stats
  city_id       text references compare_cities(id)
  metric_key    text not null           -- 5章の key
  value         numeric                 -- null = データ未取得
  unit          text not null
  period_label  text not null           -- 例 '1991〜2020年' '2014〜2023年' '2020-10-01'
  source_id     references data_sources
  checked_on    date not null           -- 確認日
  note          text
  primary key (city_id, metric_key)

compare_city_codes                      -- 不動産取引の取得に使う区のコード
  city_id       text references compare_cities(id)
  reinfolib_code text not null
  primary key (city_id, reinfolib_code)
```

- RLS は既存の方針どおり：anon は `compare_cities`（`is_published` の行）と `compare_city_stats`（公開都市の行）の select だけ。service_role は CRUD。authenticated には何も与えない
- `data_sources` に2行追加：「気象庁 平年値（1991〜2020年）」「国土交通省 水害統計調査」。国勢調査は既存の行を使う。`credit_text`・ライセンス・URL・対象時点を埋める。ライセンスは気象庁＝政府標準利用規約（CC BY 4.0 互換）、水害統計＝e-Stat の利用規約。URL は実在のものを確認して入れる
- `real_estate_transactions` に都市の行を入れられるようにする。今は町名→地区で振り分けているので、都市の取引には「都市 id」を持つ列を足すか、別の振り分け先を作るか、既存の設計を読んで一番ゆがまない方法を提案してから実装する
- `market_stats` に都市 × （土地／築20年以内／築21年以上）の行が入るようにし、`refresh_market_stats` を都市にも回す。地区の12行には影響を与えない。集計の定義（除外・期間・件数ラベル）は地区と完全に同じにする
- PGlite のマイグレーションテストに、新テーブルの権限（anon が非公開行を読めないこと）を足す

### 6.2 手入力データの流れ（`compare:sql`）

- `data/compare/cities.csv` と `data/compare/stats.csv` を作る。`stats.csv` は 7都市 × 7指標 = 49行で、**value は全部空**、`period_label`・`source`・`checked_on` も空にしておく
- `npm run compare:sql` で CSV → マイグレーション SQL を書き出す。`population:sql` と同じ流儀。値が空の行は `value = null` で入れる（画面で「データ未取得」になる）
- CSV の先頭にコメントで「値は 気象庁『過去の気象データ検索』→ 地点 → 平年値（年・月ごとの値）から」「水害被害額は e-Stat 水害統計調査 表-25 から、千円を万円に換算して10年合計」と、取り方を書いておく
- `docs/036_compare_city.md` に「私が手で埋める手順」の節を作る（URL、どの表、どの列、何を足すか、東京23区の扱い）

### 6.3 Worker（`dear-life-ingest`）

- `transactions` job に都市のコードを足す。`compare_city_codes` を読んで、年ごとに取りに行く
- 初回のバックフィルは件数が多い（区コード約80 × 5〜6年）。1日400回の上限と1.5秒間隔を守り、**数日に分けて**取る設計にする。進み具合は `ingest_runs` に残す
- 取りこぼし・失敗は今と同じく前回のデータを残し、Discord に通知
- 毎日の `refresh_market_stats` が都市の行も更新すること

### 6.4 RPC

- `screen_data()` の返り値に `compareCities`（公開都市の情報 + 指標 + 都市の `market_stats`）を追加。サイズの増分を報告する（今は約68KB／gzip 9.6KB）
- 画面側の fetch・Cache API・オフライン表示は既存のまま動くこと

## 7. 画面

### 7.1 地区くらべ `/kurabe` にタブ `t=city`

- タブ名「いまの街と」。既存5タブの右、「全項目」の左に置く。`t` の許容値に `city` を足し、知らない値は初期値に戻す今のルールを守る
- 比較相手は既存の `v` パラメータを使い回す。`v` に都市 id（`tokyo` など）が来たら都市、地区 id なら従来どおり。初期値は `tokyo`
- **PC**：左列「いまの街」（都市のプルダウン）、中央に矢印の列、右列「飯田」（選んだ地区の名前と、住まい以外は「飯田市」の注記）。行は 5章の順で、系統ごとに小見出し（雨・風・雪／水害の被害／住まい／人口）
- **スマホ**：今の「2地区で比較」と同じ2列。「4地区を一覧」は出さない
- 数字の見せ方は既存のカードと同じ（Mochiy Pop One の大きい数字＋小さい単位＋下に出典・対象・確認日）。`value` が null の行は「データ未取得」
- 矢印は中立の1色（深緑）で、上下ではなく「→」。増減の向きで色や形を変えない
- 演出：家族のドット絵が左の街から右の飯田へ歩く小さなアニメーション（既存の「次は、現地で確かめよう」の帯の絵を流用。新しい絵は描かない）。`prefers-reduced-motion` では止まった絵
- 注意書き（`notices.ts` に追加）：
  - 「気象の値は各都市の気象官署の平年値（1991〜2020年）です。市内でも場所によって差があります。」
  - 「水害被害額は住まい・店・農作物などの被害で、道路や堤防の被害は含みません。対象期間：○○年〜○○年。」
  - 「住まいの相場は、飯田側は選んだ地区、相手側は市全体の値です。」
  - 「数字は暮らしやすさの判定ではありません。」
- 出典の欄は既存の開閉式を使い、今のタブに出ている指標の出典だけを出す
- 「次のタブを比べる →」の循環に `city` を組み込む

### 7.2 防災カルテ `/karte/disaster`

- 数字カードを1枚追加「雨と風は、どれくらい？」。飯田市の `precip_annual`・`rain30_days`・`wind10_days`・`snow_depth_max`・`flood_damage_10y` を小さいカード5枚で。出典・対象・確認日つき
- カードの下に「いまの街とくらべる →」（`/kurabe?t=city` に条件を持って移る）
- 既存の避難場所カードは触らない。並びは「雨と風」→「避難場所」の順
- 印刷（`カルテの詳細`）にこのカードが入ること

### 7.3 くらし 夏のピン（避難場所）

- 吹き出しの実データ文に1文足す：「飯田の日降水量30mm以上の日は、1年に○日（平年値）。」種類は「データ」（緑の出典札）。場面のひな形 `drafts.ts` に追加し、`scenes:sql` と `check.ts` を通す
- 値が null なら出さない（今の「値がないとき」のルールどおり）

### 7.4 データについて `/about-data`

- 出典の一覧は `data_sources` から自動で出るので、新しい2行が出ることを確認
- 4節（相場の計算のしかた）に「移住元の都市の相場も同じ定義で集計している」ことを1段落足す
- 「手でまとめた情報」の節に、気象・水害・人口の手入力と確認日のことを足す

### 7.5 印刷

- 地区くらべの印刷対象に「いまの街と」を追加（チェック1個）。紙では都市1つ（今選んでいる `v`）と飯田を並べる
- 長い表は既存の「高さを測って次の紙へ」の仕組みに乗せる

## 8. テスト

- 既存テスト（約80ファイル）が全部通ること
