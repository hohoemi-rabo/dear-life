## 1. コンセプト

### 1.1 ひと言でいうと

> **家族に合わせて、飯田の暮らしを見える化**
>
> 移住を考える家族が、暮らし方をゲーム感覚で**選んで**、その条件で過ごす春夏秋冬の暮らしを**見て**、相場・学校・交通・防災などの本物のデータで**確かめる**、登録不要の Web サービス。

| 項目 | 内容 |
| --- | --- |
| 名前 | DearLife（ディアライフ）／日本語名：飯田移住カルテ |
| 対象者 | 飯田市への移住を考えている家族全般（U ターンに限らない） |
| 使う場面 | 候補地の情報集めを始めてから、現地見学・移住相談の前まで |
| 対象地区 | 上郷・鼎・伊賀良・中心市街地の4地区だけ（市全域とは案内しない） |
| 形 | スマホ優先の Web サービス（PC でも見られる）。ホーム画面に追加してアプリのように使える。登録・ログインなし |
| 作り手 | 地元の個人。行政でも不動産会社でもない |

### 1.2 なぜ作るのか（解きたい問題）

- 市や県の移住サイトは、気候・支援金・相談窓口など**市全体の情報**がそろっている。一方で、移住を考える家族が本当に迷うのは「**どの地区で**、うちの家族が**どう暮らすか**」で、地区（旧町村）ごとの違いは見えにくい
- 情報をカードで並べるだけでは、既存のサイトとの違いが一目で伝わらない
- そこで、市全体の情報は市や県のサイトに任せ、このサービスは**地区単位の暮らし**に絞る。そして、暮らし方を選ぶこと自体をゲームのようにし、その結果を季節の場面で見せる（着想元：[80億分の1（1in8b.life）](https://1in8b.life/ja/about/)）

### 1.3 体験の3ステップ

| ステップ | 画面 | 利用者がすること | このサービスの役割 |
| --- | --- | --- | --- |
| 01 えらぶ | `/erabu` | 地区・家族・家・車・大切なことを、タップだけで選ぶ | 選ぶたびに、その地区の本物のデータを短く返す。プレビューの絵に家族・家・車が増えていく |
| 02 くらしを見る | `/kurashi` | 春夏秋冬の風景を切りかえ、気になる場所のピンを押す | その条件で過ごす季節の場面（入園・入学、大雨と避難、地区の行事、雪とおでかけ）を、実データの文と出典で見せる |
| 03 カルテで確かめる | `/karte` | 場面の根拠を、分野ごとに数字で確かめる | 選んだ条件で並びを変えたカードと、項目ごとの詳細（数字・一覧・現地で確かめたいこと・出典）を出す |
| その先 | `/kurabe`・`/chizu` | 4地区を並べてくらべる、地図で場所を確かめる | 同じ項目で4地区を並べる（順位は付けない）。施設と学区を地図に出す |

ゴールは「地区の暮らしが想像でき、**現地で見たい場所・窓口で聞きたいことが具体的になる**」こと。カルテの「わが家の確認ポイント」（はじめの名前は「わが家の確認メモ」）「現地で確かめたいこと」と印刷は、このためにある。

### 1.4 既存サービスとの違い

1. **選んで、季節の暮らしを見る**：家族・地区・家・車を選ぶと、その条件で過ごす春夏秋冬の場面が見られる。選んだ条件で場面の中身が変わる（サービスの顔）
2. **地区の行事まで見せる**：地区（公民館）ごとの行事を季節の場面に出す。移住を考える人が知りたいのに、市や県の移住情報には載っていない部分（4地区×4季節で28件）
3. **地区ごとの相場を件数つきで示す**：取引データを地区単位で集計し、真ん中の値・幅・件数まで見せる
4. **地区を横に並べてくらべられる**：4地区を同じ項目で比べる
5. **登録なしで、地元の人が作る**：行政でも不動産会社でもない立場で、物件の勧誘をしない

### 1.5 見せ方の軸：「絵はイメージ、数字は本物」

- 風景・人物はゆるいゲーム画面のような絵（生成AIの絵と、ドット絵のアイコン）。**実際の景観・配置・距離とは違うイメージ**であることを、トップ・くらし・データについてで断る
- その中に出す数字・施設名・行事は、**出典・対象時点・確認日つきの実データだけ**。このギャップをいちばん伝えたいところとし、数字の正確さと出典の表示は崩さない
- 見た目でも分ける：絵の側は季節の色・ドット風の枠、実データの側はふつうのフォント（M PLUS Rounded 1c）と基本色（深緑・生成り）で、件数・出典・確認日を必ず添える
- 場面の文は「データ／地区の情報／想定」の3種類に分け、印で見分けられるようにする。想定の文に数字・施設名・評価は入れない

### 1.6 大切にしている立場（やらないこと）

| やらないこと | 理由 |
| --- | --- |
| 点数化・ランキング・「おすすめ地区」の判定・「暮らしやすさ」の評価 | 家族ごとに大切なことは違う。判断は利用者に任せ、事実だけを並べる |
| 「便利」「不便」「近い」などの評価や距離の言い方 | 家の位置を持たないので距離は言えない。本数が少ないことも事実のまま見せる |
| AI で毎回文章を作る・ランダムな出来事 | 同じ条件なら何度見ても同じ場面にし、裏づけのない出来事を書かない |
| 作り話で埋める | 行事が集まっていない季節は「準備中」、データがないときは「該当なし」と「データ未取得」を分けて出す |
| 支援制度の「対象になります」判定 | 必ず公式ページと窓口につなぐ |
| 会員登録・条件の保存・アクセス解析 | 選んだ条件は URL にだけ持ち、サーバーに送らない。個人の情報を持たない |
| 物件の紹介・勧誘、国や市のサービスだと誤認させる名前やマーク | 個人が公開データをもとに作ったものだと、全画面の下に書く |

### 1.7 公共交通と gofreely

- 「**車がなくても、この町でこう暮らせる**」を見せるのも狙いの1つ。冬・車0台の場面では、時刻表（GTFS）にある本物のバスの便・本数を出し、「本数や時間帯によっては、車なしの暮らしが難しいことがあります」と添える
- まさゆきさんの別アプリ **gofreely**（電車・バス・乗合タクシーの乗り継ぎ検索）と2作品で、公共交通オープンデータチャレンジ2026（締切 2027-01-11）に応募する予定。DearLife が「乗ってみよう」と思わせる入口、gofreely が「どの便で行けるか」を調べる手段という役割分担で、場面とカルテの便から gofreely へリンクする
- 応募に必須のデータは、GTFS データリポジトリの南信州のバス（市民バス・信南交通・飯田☆中津川線）

### 1.8 運営のしかた

- 費用：ほぼ無料プランで運用（Cloudflare Workers だけ月5ドル）。画面は静的ファイルで、外部 API を呼ぶのは毎日1回の定期取得だけなので、利用者が増えても API へのアクセスは増えない
- データの更新：相場・学区・バスの新しい版の確認は自動。支援制度（月1回）と行事（年1回）はまさゆきさんが確かめて直す

## 4. 条件モデル（URL パラメータ）

条件は URL にだけ持ち、サーバーに送らず保存もしない（F-02）。コードは `src/lib/conditions/`。

| パラメータ | 項目 | 値 | 初期値 | 備考 |
| --- | --- | --- | --- | --- |
| `d` | 住む地区 | `kamisato` / `kanae` / `igara` / `chushin` | なし | えらぶでは必須 |
| `a` | 大人 | 1〜2 | 2 | 範囲外は端に丸める |
| `k` | 子ども | 0〜8 | 1 | 絵に出すのは4人まで。5人目からは「＋N人」の札 |
| `o` | 大人1人のときの親 | `mother` / `father` | mother | 大人1人のときだけ書く |
| `h` | 家 | `new` 買う・新しめ（築20年以内）／`old` 買う・古め（築21年以上）／`rent` 借りる | new | |
| `c` | 車 | `0` / `1` / `2`（2台以上） | なし | 2026-11-06 から必須。`c` のない古い URL は未選択として開き、「車あり」と同じに扱う |
| `p` | 大切にしたいこと | `housing` `childcare` `transport` `disaster` `population` をカンマ区切り | なし | 任意・複数。支援制度・公共施設は選択肢にない。順番は既定の並びにそろえる |
| `s` | 季節（くらし） | `spring` `summer` `autumn` `winter` | spring | 全画面で持ち回る |
| `q` | えらぶの今の質問 | `district` `family` `housing` `car` `priorities` | district | えらぶだけ |
| `t` | 地区くらべのタブ | `housing` `school` `transport` `population` `events` `city` `all` | housing | 地区くらべだけ。`city` は「いまの街と」（041） |
| `v` | 地区くらべ（スマホ）の比較相手 | 地区 id か `all` | 最初の別の地区 | 地区くらべだけ |
| `m` | 「いまの街と」で比べる都市 | `tokyo` `yokohama` `nagoya` `osaka` `nagano` `matsumoto` | tokyo | 地区くらべだけ（041）。`v` と分けて、タブを行き来しても選んだ都市が残る |

- 知らない値は黙って初期値に戻す
- 条件の書きかえは `router.replace`（履歴を増やさない）。えらぶの質問の移動だけ `router.push`（ブラウザの戻るで前の質問へ）
- 氏名・住所・年齢は持たない

### 条件が反映される場所

### 5.7 05 地図 `/chizu`（021・032）

- Google マップ（Maps JavaScript API）。データは RPC `map_data()`

| 秘密情報 | `SUPABASE_SERVICE_ROLE_KEY`・`REINFOLIB_API_KEY`・`DISCORD_WEBHOOK_URL` は Worker の Secret。画面に埋め込むのは Supabase の URL・publishable key と Google Maps のキー・Map ID だけ |
| セキュリティヘッダー | CSP などの設定はない |
| アクセス解析 | なし（Cloudflare の Worker ログだけ） |
| テスト | Vitest + Testing Library（jsdom）、テストファイル約80。マイグレーションは PGlite に当てて権限を確かめる。E2E テストはなく、実機の確認はチケットに手で記録 |
| 費用 | Cloudflare Workers Paid（月5ドル）。ほかは無料プラン。Google Maps は1日の上限と予算アラートつき |
