# 014 条件モデル・URLパラメータ・反映ルール

- 主な要件：F-01（質問と初期値）、F-02（条件の保持）、4章（選択の反映ルール）
- 依存：002

## 目的

選んだ条件を表す型、URL パラメータとの相互変換、4章の反映ルール（カードの並び順・場面の分岐・えらぶ画面の返事の種類）を、画面から独立した純粋な関数としてまとめ、テストで固める。

## 仕様メモ

### 条件

| 項目 | 値 | 飛ばしたときの初期値 |
| --- | --- | --- |
| 家族 | 大人の人数・子どもの人数 | 大人2人・子ども1人 |
| 住む地区 | 上郷／鼎／伊賀良／中心市街地 | （必須。案：未選択なら選ぶまで次へ進めない） |
| 家 | 買う・新しめ／買う・古め／借りる | 買う・新しめ |
| 車 | 0台／1台／2台以上（任意） | 未選択 |
| 大切にしたいこと | 住まい・子育て・学校／交通／防災／人口 から複数（任意）。支援制度は選択肢に入れない | なし |

- 氏名・住所・年齢は聞かない
- URL パラメータで持ち、サーバーに送らない・保存しない。将来の「URL で共有」でそのまま使える形にする
- パラメータ名は短く固定する（案：`d`=地区、`a`=大人、`k`=子ども、`h`=家、`c`=車、`p`=大切にしたいこと（カンマ区切り））
- 不正な値・範囲外の値は初期値に戻す（外部入力の検証）
- 静的書き出しなので、ページでは `useSearchParams()` を使う Client Component で読み、`<Suspense>` で囲む

### 反映ルール（4章）

- カルテの既定の並び：住まい → 子育て・学校 → 交通 → 防災 → 人口 → 支援制度（支援制度は常に最後）
- 大切にしたいことで選んだ分野を先に並べ、「○○に関する情報を先に表示しています」の一文を作る。選ばなかった分野も隠さない
- 子ども1人以上：「子育て・学校」を大切にしたいことのすぐ後ろへ。0人：下の方へ
- 車0台：交通カードを上げ、「本数や時間帯によっては、車なしの暮らしが難しいことがあります」を添える。1台以上・未選択：並びは変えない
- 場面の分岐：春＝子どもあり→入園・入学／なし→公共施設、秋＝子どもあり→子ども向け行事を優先、冬＝車0台→バス／それ以外→車（凍結・スタッドレス）、冬＝買う・古め→古い家の寒さの想定文を入れてよい
- 点数化・ランキング・おすすめ判定はしない
